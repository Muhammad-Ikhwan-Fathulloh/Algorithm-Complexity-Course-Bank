Dynamic Programming I

Kalau rekursi naif menghitung hal yang sama berulang kali, DP menyimpan hasilnya. Dua prinsip: overlapping subproblems dan optimal substructure. Hasilnya? Eksponensial jadi polinomial.

PETA LANGKAH · KENAPA PENTING

Peta langkah: cara merancang DP

1. Cek dua syarat
Subproblem harus tumpang tindih (sama dihitung berulang) dan punya substruktur optimal (solusi besar tersusun dari solusi kecil).
2. Definisikan state
Tentukan arti dp[i] atau dp[i][w] dengan kalimat yang jelas. Kesalahan di sini sering menjadi sumber bug.
3. Tulis rumus transisi
Nyatakan dp[state] dari state yang lebih kecil. Pastikan setiap pilihan dicoba.
4. Tentukan base case dan urutan
Isi kasus kecil dulu. Pada bottom-up, urutan pengisian harus menjamin nilai sudah tersedia.
5. Pilih implementasi
Top-down (memoization) mudah ditulis. Bottom-up (tabel) lebih cepat dan bisa dioptimasi memorinya.
Kenapa penting: DP mengubah pencarian eksponensial menjadi polinomial, asalkan subproblemnya sedikit. Knapsack 0/1 adalah contoh klasik: Θ(n·W) yang pseudo-polinomial.
Θ(n·W) bergantung pada nilai kapasitas W, bukan jumlah bit. Jika W sangat besar, algoritma ini tetap lambat walaupun terlihat polinomial.
PRINSIP DASAR

Dua syarat DP berlaku

1. Overlapping Subproblems

Rekursi naif memecah masalah menjadi submasalah - tapi submasalah yang sama dihitung berulang kali. DP menyimpan hasil setiap submasalah (memoize) sehingga hanya dihitung sekali.

2. Optimal Substructure

Solusi optimal masalah bisa dibangun dari solusi optimal submasalahnya. Kalau submasalah harus diselesaikan secara independen, DP tidak berlaku (lihat Activity Selection - Greedy lebih tepat).

Analogi - tangga dengan biaya. Untuk naik ke anak tangga ke-n dengan biaya minimum: kamu datang dari tangga n-1 atau n-2. Keputusan optimal di tangga ke-n bergantung pada keputusan optimal di bawahnya. Inilah optimal substructure.

Fibonacci: dari O(2ⁿ) ke O(n)

CaraKompleksitas
Rekursi naifO(2ⁿ)
Memoization (top-down)O(n)
Tabulation (bottom-up)O(n), O(1) ruang
from functools import lru_cache
@lru_cache(None)
def fib(n):                    # top-down
    if n <= 1: return n
    return fib(n-1) + fib(n-2)

def fib_tab(n):                # bottom-up
    a, b = 0, 1
    for _ in range(n): a, b = b, a+b
    return a
BAGIAN 1 · 0/1 KNAPSACK

Knapsack 0/1 - Θ(n·W) pseudo-polinomial

n item, tiap punya berat wᵢ dan nilai vᵢ. Kapasitas tas W. Maksimalkan nilai, tiap item diambil atau tidak (0 atau 1).

Rekurens DP:
dp[i][w] = max nilai pakai item 1..i dengan berat ≤ w
dp[i][w] = dp[i-1][w]                   (tidak ambil item i)
           max dengan dp[i-1][w-wᵢ]+vᵢ  (ambil, kalau wᵢ≤w) 
def knapsack(weights, values, W):
    n = len(weights)
    dp = [[0]*(W+1) for _ in range(n+1)]
    for i in range(1, n+1):
        for w in range(W+1):
            dp[i][w] = dp[i-1][w]   # tidak ambil
            if weights[i-1] <= w:
                dp[i][w] = max(dp[i][w],
                    dp[i-1][w-weights[i-1]] + values[i-1])
    return dp[n][W]  # O(n*W)

BAGIAN 2 · COIN CHANGE

Coin Change - minimum koin untuk jumlah target

Diberikan koin-koin dengan denominasi coins[] dan target amount, cari jumlah minimum koin yang diperlukan.

def coin_change(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0               # base case
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a-c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
# T(amount, |coins|): O(amount × |coins|)
Greedy tidak selalu benar di sini! Koin [1,3,4], target=6: greedy ambil 4 → perlu 3 koin (4+1+1). DP temukan: 3+3 = 2 koin. Greedy gagal karena tidak ada optimal substructure untuk greedy.

BAGIAN 3 · STRATEGI DP

Top-down vs Bottom-up: dua cara implementasi DP

Top-down (Memoization)

Tulis rekursi naif, tambahkan cache. Hanya hitung submasalah yang benar-benar dibutuhkan ("lazy"). Mudah dikode, tapi ada overhead rekursi (stack calls).

from functools import lru_cache
@lru_cache(None)
def dp(i, w):
    if i == 0: return 0
    skip = dp(i-1, w)
    if weights[i-1] > w: return skip
    return max(skip, dp(i-1,w-weights[i-1])+values[i-1])

Bottom-up (Tabulation)

Isi tabel dari submasalah terkecil ke terbesar. Tidak ada rekursi → tidak ada stack overflow. Bisa dioptimasi ruang (misalnya 1D array untuk Knapsack).

def dp_tab(weights, values, W):
    dp = [0] * (W + 1)
    for i in range(len(weights)):
        for w in range(W, weights[i]-1, -1):
            dp[w] = max(dp[w], dp[w-weights[i]]+values[i])
    return dp[W]  # O(n*W) waktu, O(W) ruang

Analogi: top-down = cari di kamus mulai dari halaman depan, melompat ke referensi. Bottom-up = baca kamus dari awal sampai akhir, catat semua. Yang pertama lebih natural; yang kedua lebih efisien kalau semua entry dibutuhkan.

KUNCI JAWABAN

Kunci Dynamic Programming I

1

Overlapping subproblems: submasalah yang sama muncul lebih dari sekali dalam rekursi. Optimal substructure: solusi optimal bisa dibangun dari solusi optimal submasalahnya. Contoh keduanya: knapsack, fibonacci. Hanya substructure tapi tidak overlapping: activity selection (greedy lebih tepat).

2

Bottom-up Fibonacci: n-1 operasi = 9 operasi untuk Fib(10). Rekursi naif: T(n) = T(n-1)+T(n-2)+1, tumbuh eksponensial ≈ 2^10 ≈ 1024 pemanggilan. DP 100× lebih efisien di sini, makin jauh makin besar selisihnya.

3

Tabel DP: dp[3][5] = 22. Ambil item 1 (b=1,v=6) + item 3 (b=3,v=12) = berat 4, nilai 18? Cek lagi: item dengan nilai terbesar adalah [2,3] nilai [10,12] berat total 5 = nilai 22. Benar: ambil item 2 dan 3.

4

Pseudo-polinomial karena O(n·W) - di mana W angkanya, bukan jumlah bit. Representasi W butuh log₂W bit, jadi W = 2^(log₂W) → kompleksitas sebenarnya O(n · 2^(jumlah bit W)) = eksponensial dalam ukuran input. Berbeda dari "polinomial terhadap panjang input".

5

Koin AS [1,5,10,25]: greedy benar di sini karena denominasinya dipilih dengan baik. amount=41 → 25+10+5+1 = 4 koin (greedy ✓). amount=63 → 25+25+10+3×1 = 7 koin (greedy ✓). Greedy gagal untuk sistem koin acak seperti [1,3,4].
