Dynamic Programming I

Kalau rekursi naif menghitung hal yang sama berulang kali, DP menyimpan hasilnya. Dua prinsip: overlapping subproblems dan optimal substructure. Hasilnya? Eksponensial jadi polinomial.

PETA LANGKAH · KENAPA PENTING

Peta langkah: cara merancang DP

1. Cek dua syarat
Subproblem harus tumpang tindih (sama dihitung berulang) dan punya substruktur optimal (solusi besar tersusun dari solusi kecil).
2. Definisikan state
Tentukan arti dp[i] atau dp[i][w] dengan kalimat yang jelas. Kesalahan di sini sering menjadi sumber bug.
3. Tulis rumus transisi
Nyatakan dp[state] dari state yang lebih kecil. Pastikan setiap pilihan dicoba.
4. Tentukan base case dan urutan
Isi kasus kecil dulu. Pada bottom-up, urutan pengisian harus menjamin nilai sudah tersedia.
5. Pilih implementasi
Top-down (memoization) mudah ditulis. Bottom-up (tabel) lebih cepat dan bisa dioptimasi memorinya.
Kenapa penting: DP mengubah pencarian eksponensial menjadi polinomial, asalkan subproblemnya sedikit. Knapsack 0/1 adalah contoh klasik: Θ(n·W) yang pseudo-polinomial.
Θ(n·W) bergantung pada nilai kapasitas W, bukan jumlah bit. Jika W sangat besar, algoritma ini tetap lambat walaupun terlihat polinomial.

WHAT - Apa itu Dynamic Programming?

Teknik menyelesaikan masalah dengan memecahnya menjadi subsoal yang tumpang-tindih, menyelesaikan setiap subsoal sekali, dan menyimpan hasilnya.

State

Parameter yang mengidentifikasi subsoal, misalnya K[i][w].

Transisi

Rumus rekurens yang menghitung state dari state lain.

Tabel/memo

Penyimpan hasil agar tidak dihitung ulang.

Contoh: Fibonacci: F(n) = F(n−1) + F(n−2), simpan setiap F(k) di tabel.

WHY - Mengapa DP dibutuhkan?

Karena rekursi naif pada subsoal yang tumpang-tindih bisa eksponensial.

Eksponensial → polinomial

fib naif Θ(φⁿ) menjadi Θ(n).

Greedy tidak cukup

0/1 knapsack dan coin change umum tidak bisa diselesaikan greedy.

Optimal terjamin

DP mencoba semua pilihan secara sistematis tanpa mengulang.

Contoh: fib(50) naif ±28 miliar panggilan; dengan DP 50 langkah.

HOW - Bagaimana merancang DP?

Empat langkah baku:

1. Definisikan state

Apa arti dp[i][w]? Tulis dalam kalimat.

2. Tulis transisi & basis

dp[i][w] = maks(…); dp[0][*] = 0.

3. Tentukan urutan & hitung biaya

Isi tabel dari basis; biaya = #state × transisi.

Contoh: Coin change: state C[a]; transisi 1 + min C[a − c]; basis C[0] = 0; biaya Θ(A·k).
PRINSIP DASAR

Dua syarat DP berlaku

1. Overlapping Subproblems

Rekursi naif memecah masalah menjadi submasalah - tapi submasalah yang sama dihitung berulang kali. DP menyimpan hasil setiap submasalah (memoize) sehingga hanya dihitung sekali.

2. Optimal Substructure

Solusi optimal masalah bisa dibangun dari solusi optimal submasalahnya. Kalau submasalah harus diselesaikan secara independen, DP tidak berlaku (lihat Activity Selection - Greedy lebih tepat).

Analogi - tangga dengan biaya. Untuk naik ke anak tangga ke-n dengan biaya minimum: kamu datang dari tangga n-1 atau n-2. Keputusan optimal di tangga ke-n bergantung pada keputusan optimal di bawahnya. Inilah optimal substructure.

Fibonacci: dari O(2ⁿ) ke O(n)

CaraKompleksitas
Rekursi naifO(2ⁿ)
Memoization (top-down)O(n)
Tabulation (bottom-up)O(n), O(1) ruang
from functools import lru_cache
@lru_cache(None)
def fib(n):                    # top-down
    if n <= 1: return n
    return fib(n-1) + fib(n-2)

def fib_tab(n):                # bottom-up
    a, b = 0, 1
    for _ in range(n): a, b = b, a+b
    return a
BAGIAN 3 · STRATEGI DP

Top-down vs Bottom-up: dua cara implementasi DP

Top-down (Memoization)

Tulis rekursi naif, tambahkan cache. Hanya hitung submasalah yang benar-benar dibutuhkan ("lazy"). Mudah dikode, tapi ada overhead rekursi (stack calls).

from functools import lru_cache
@lru_cache(None)
def dp(i, w):
    if i == 0: return 0
    skip = dp(i-1, w)
    if weights[i-1] > w: return skip
    return max(skip, dp(i-1,w-weights[i-1])+values[i-1])

Bottom-up (Tabulation)

Isi tabel dari submasalah terkecil ke terbesar. Tidak ada rekursi → tidak ada stack overflow. Bisa dioptimasi ruang (misalnya 1D array untuk Knapsack).

def dp_tab(weights, values, W):
    dp = [0] * (W + 1)
    for i in range(len(weights)):
        for w in range(W, weights[i]-1, -1):
            dp[w] = max(dp[w], dp[w-weights[i]]+values[i])
    return dp[W]  # O(n*W) waktu, O(W) ruang
AspekTop-downBottom-up
Kemudahan kode✓ MudahPerlu dipikir urutan
Submasalah yg dihitungHanya yg perluSemua
Overhead rekursiAda (stack calls)✓ Tidak ada
Optimasi ruangSulit✓ Mudah (1D array)
Stack overflow?Bisa (n besar)✓ Tidak
Analogi: top-down = cari di kamus mulai dari halaman depan, melompat ke referensi. Bottom-up = baca kamus dari awal sampai akhir, catat semua. Yang pertama lebih natural; yang kedua lebih efisien kalau semua entry dibutuhkan.

Rekurens Knapsack 0/1

K[i][w] = maks( K[i−1][w],  vi + K[i−1][w − wi] )   (jika wi ≤ w);   Θ(n·W)

Cara membaca rumus ini

“K i w sama dengan maksimum antara K i kurang satu w, yaitu tidak mengambil item i, dan v i ditambah K i kurang satu, w kurang w i, yaitu mengambil item i, asalkan berat item i tidak melebihi w.”
1

K[i][w]

nilai terbaik memakai item 1..i dengan kapasitas w.

2

Pilihan 1: tidak ambil

nilainya sama dengan solusi tanpa item i: K[i−1][w].

3

Pilihan 2: ambil

dapat vᵢ, kapasitas tersisa w − wᵢ untuk item 1..i−1.

4

Θ(nW) pseudo-polinomial

polinomial terhadap NILAI W, bukan terhadap panjang bit W.

Arti tiap simbol

iitem yang sedang dipertimbangkan
wkapasitas yang tersedia
vᵢ, wᵢnilai dan berat item i
Wkapasitas total
Intuisinya: Setiap item hanya punya dua nasib: diambil atau tidak. Rumus mencoba keduanya dan menyimpan yang terbaik, sehingga 2ⁿ kombinasi diringkas menjadi tabel n × W.

Rekurens Coin Change

Cara membaca rumus ini

“C nol sama dengan nol. C a sama dengan satu ditambah minimum dari C a kurang c, untuk setiap koin c yang nilainya tidak melebihi a. Biayanya Theta A kali k.”
1

C[a]

banyaknya koin minimum untuk membentuk jumlah a.

2

1 +

kita memakai satu koin c sebagai koin terakhir.

3

C[a − c]

sisa jumlah harus dibentuk secara optimal juga (optimal substructure).

4

min

coba semua jenis koin sebagai “koin terakhir”, ambil yang terbaik.

BAGIAN 1 · 0/1 KNAPSACK

Knapsack 0/1 - Θ(n·W) pseudo-polinomial

n item, tiap punya berat wᵢ dan nilai vᵢ. Kapasitas tas W. Maksimalkan nilai, tiap item diambil atau tidak (0 atau 1).

Rekurens DP:
dp[i][w] = max nilai pakai item 1..i dengan berat ≤ w
dp[i][w] = dp[i-1][w]                   (tidak ambil item i)
           max dengan dp[i-1][w-wᵢ]+vᵢ  (ambil, kalau wᵢ≤w) 
def knapsack(weights, values, W):
    n = len(weights)
    dp = [[0]*(W+1) for _ in range(n+1)]
    for i in range(1, n+1):
        for w in range(W+1):
            dp[i][w] = dp[i-1][w]   # tidak ambil
            if weights[i-1] <= w:
                dp[i][w] = max(dp[i][w],
                    dp[i-1][w-weights[i-1]] + values[i-1])
    return dp[n][W]  # O(n*W)

Cara membaca rumus:
• dp[i][w] = nilai maksimum memakai item 1 sampai i dengan kapasitas w.
• Dua pilihan: tidak mengambil item i → dp[i−1][w]; atau mengambil item i (jika wᵢ ≤ w) → dp[i−1][w−wᵢ] + vᵢ.
• Ambil yang lebih besar dari kedua pilihan. Tabel n × W menghasilkan Θ(n·W).
BAGIAN 2 · COIN CHANGE

Coin Change - minimum koin untuk jumlah target

Diberikan koin-koin dengan denominasi coins[] dan target amount, cari jumlah minimum koin yang diperlukan.

def coin_change(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0               # base case
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a-c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
# T(amount, |coins|): O(amount × |coins|)
Greedy tidak selalu benar di sini! Koin [1,3,4], target=6: greedy ambil 4 → perlu 3 koin (4+1+1). DP temukan: 3+3 = 2 koin. Greedy gagal karena tidak ada optimal substructure untuk greedy.

Cara membaca rumus:
• dp[x] = jumlah koin minimum untuk mencapai jumlah x.

• Contoh: koin [1,3,4], target 6 → dp[6] = dp[3] + 1 = 2 (koin 3 + 3).

from functools import lru_cache
calls = 0
@lru_cache(maxsize=None)
def fib(n):
    global calls; calls += 1
    return n if n < 2 else fib(n-1) + fib(n-2)

fib(80); print(calls)   # 81 = banyaknya subsoal unik

Dari hitungan ke kode: Rekurens Knapsack 0/1

Kode Python

def knapsack(items, W):
    K = [0] * (W + 1)
    for v, w in items:
        for cap in range(W, w - 1, -1):      # mundur: tiap item sekali
            K[cap] = max(K[cap], v + K[cap - w])
    return K[W]

print(knapsack([(60,1), (100,2), (120,3)], 5))   # 220

Dan dengan jejak eksekusi

K[5] = 220 (ambil B + C) setelah 12 pembaruan sel.

Cara membaca jejak: Setiap baris = satu nilai a. Coba setiap koin sebagai koin terakhir (kolom c = 1, 3, 4), ambil yang paling kecil. Bagian yang disorot = yang berubah/dipilih pada langkah itu.
akoin 1koin 3koin 4C[a]
1C[0]+1 = 1--1
2C[1]+1 = 2--2
3C[2]+1 = 3C[0]+1 = 1-1
4C[3]+1 = 2C[1]+1 = 2C[0]+1 = 11
5C[4]+1 = 2C[2]+1 = 3C[1]+1 = 22
6C[5]+1 = 3C[3]+1 = 2C[2]+1 = 32
7C[6]+1 = 3C[4]+1 = 2C[3]+1 = 22
Hasil akhir jejak: C[6] = 2 (3 + 3) dan C[7] = 2 (3 + 4).
Bagian B · Teknikal · Rumus 3/3 - kode Python

Dari hitungan ke kode: Rekurens Coin Change

Kode Python

def coin_change(coins, A):
    INF = float("inf")
    C = [0] + [INF] * A
    for a in range(1, A + 1):
        C[a] = 1 + min((C[a - c] for c in coins if c <= a), default=INF)
    return C[A]

print(coin_change([1, 3, 4], 6))   # 2

Cocokkan dengan hitung manual

Jalankan kode, lalu bandingkan dengan hasil yang sudah dihitung dengan tangan:

C[6] = 2 (3 + 3), sedangkan greedy 4 + 1 + 1 = 3 koin.

Dan dengan jejak eksekusi

C[6] = 2 (3 + 3) dan C[7] = 2 (3 + 4).

KUNCI JAWABAN

Kunci Dynamic Programming I

1

Overlapping subproblems: submasalah yang sama muncul lebih dari sekali dalam rekursi. Optimal substructure: solusi optimal bisa dibangun dari solusi optimal submasalahnya. Contoh keduanya: knapsack, fibonacci. Hanya substructure tapi tidak overlapping: activity selection (greedy lebih tepat).

2

Bottom-up Fibonacci: n-1 operasi = 9 operasi untuk Fib(10). Rekursi naif: T(n) = T(n-1)+T(n-2)+1, tumbuh eksponensial ≈ 2^10 ≈ 1024 pemanggilan. DP 100× lebih efisien di sini, makin jauh makin besar selisihnya.

3

Tabel DP: dp[3][5] = 22. Ambil item 1 (b=1,v=6) + item 3 (b=3,v=12) = berat 4, nilai 18? Cek lagi: item dengan nilai terbesar adalah [2,3] nilai [10,12] berat total 5 = nilai 22. Benar: ambil item 2 dan 3.

4

Pseudo-polinomial karena O(n·W) - di mana W angkanya, bukan jumlah bit. Representasi W butuh log₂W bit, jadi W = 2^(log₂W) → kompleksitas sebenarnya O(n · 2^(jumlah bit W)) = eksponensial dalam ukuran input. Berbeda dari "polinomial terhadap panjang input".

5

Koin AS [1,5,10,25]: greedy benar di sini karena denominasinya dipilih dengan baik. amount=41 → 25+10+5+1 = 4 koin (greedy ✓). amount=63 → 25+25+10+3×1 = 7 koin (greedy ✓). Greedy gagal untuk sistem koin acak seperti [1,3,4].

Menaksir biaya DP sebelum menulis kode

Implementasi di proyek nyata

Sebelum menerapkan DP di produksi, engineer menghitung ukuran tabelnya. Contoh: menyelaraskan dua teks 100.000 karakter dengan LCS butuh 10¹⁰ sel - terlalu besar memori. Rumus ini yang membuat git diff memakai algoritma Myers (O(ND)) alih-alih tabel penuh.

Angka-angka di kasus ini

1

Fibonacci

n subsoal × O(1) = Θ(n).

2

Knapsack

(n × W) subsoal × 2 pilihan = Θ(nW).

3

Coin change

A subsoal × k jenis koin = Θ(Ak).

4

LCS

(m × n) subsoal × O(1) = Θ(mn).

Bawa pulang: Sebelum menulis DP, tulis dulu: state apa, berapa banyak, dan berapa kerja per state.

Memilih proyek dengan anggaran terbatas

Implementasi di proyek nyata

Memilih fitur/proyek yang dikerjakan sprint ini (nilai bisnis vs story point), memilih iklan dalam slot durasi, atau memuat kontainer. Untuk W sangat besar (misalnya anggaran dalam rupiah), skala W diperkecil (dalam juta) agar tabel muat.

Angka-angka di kasus ini

1

Item (v, w)

A(60,1), B(100,2), C(120,3); W = 5.

2

Baris A

K[1][w≥1] = 60.

3

Baris B

K[2][3] = maks(60, 100 + K[1][1]) = 160.

4

Baris C

K[3][5] = maks(K[2][5]=160, 120 + K[2][2]=100) = 220 → pilih B + C.

Bawa pulang: Knapsack 0/1 = dua pilihan per item, tabel n × W. Hemat memori: satu baris diisi dari kanan ke kiri.
