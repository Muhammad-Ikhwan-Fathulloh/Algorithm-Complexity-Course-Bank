PETA LANGKAH · KENAPA PENTING

Peta langkah: ketika solusi optimal terlalu mahal

1. Tentukan target
Apakah cukup solusi yang dekat optimum (ρ-approximation), atau solusi yang dihitung dengan cepat dan kadang salah?
2. Pilih strategi
Greedy, pembulatan LP, atau randomized. Setiap strategi punya jaminan dan biaya yang berbeda.
3. Buktikan rasio
Tunjukkan bahwa hasil algoritma tidak lebih dari ρ kali optimum, dengan membandingkannya terhadap batas bawah.
4. Pilih jenis randomized
Las Vegas selalu benar dengan waktu acak. Monte Carlo selalu cepat tetapi bisa salah dengan peluang kecil.
5. Skala besar
Untuk pencarian mirip gunakan LSH atau HNSW. Untuk attention Transformer, FlashAttention mengurangi biaya memori.
Kenapa penting: Banyak masalah nyata terlalu sulit untuk dipecahkan secara optimal. Aproksimasi dan randomisasi memberi jaminan yang jelas tanpa menunggu selamanya.
Rasio aproksimasi adalah jaminan terburuk. Pada praktiknya hasilnya sering jauh lebih baik, tetapi tetap harus diuji secara empiris.
BAGIAN 1 · ALGORITMA APROKSIMASI

ρ-approximation - solusi yang pasti tidak jauh dari optimal

Algoritma A adalah ρ-approximation jika untuk semua input, solusinya tidak lebih dari ρ kali solusi optimal:

Untuk minimasi: C(A) ≤ ρ · C(OPT)
Untuk maksimasi: C(A) ≥ (1/ρ) · C(OPT)
ρ = 1 berarti optimal; ρ = 2 berarti paling buruk 2× optimal

Vertex Cover 2-aproksimasi:

def approx_vertex_cover(graph):
    cover = set()
    edges = set(graph.edges())
    while edges:
        # ambil edge sembarang
        u, v = edges.pop()
        cover.add(u); cover.add(v)
        # hapus semua edge yang menyentuh u atau v
        edges = {e for e in edges
                 if u not in e and v not in e}
    return cover  # |cover| ≤ 2 × OPT
Mengapa ≤ 2×? Setiap edge yang dipilih algoritma adalah anggota matching M. Vertex Cover minimum harus menutup tiap edge di M → butuh ≥ |M| vertex. Algoritma pakai 2|M| vertex → rasio ≤ 2.

Analogi - pembelian massal. Tidak tahu harga optimal, tapi dengan greedy matching kita bisa jamin tidak lebih boros dari 2× harga terbaik yang mungkin. Jaminan ini berlaku untuk semua input - bukan rata-rata.
BAGIAN 2 · ALGORITMA RANDOMIZED

Las Vegas vs Monte Carlo - dua filosofi randomized

Las Vegas - Selalu benar, waktu random

Hasil selalu benar, tapi waktu eksekusi bervariasi secara random. Contoh: Randomized QuickSort - pivot dipilih acak → expected O(n log n) untuk semua input, bukan hanya rata-rata.

import random
def rand_quicksort(A):
    if len(A) <= 1: return A
    pivot = random.choice(A)  # pilih acak!
    left  = [x for x in A if x < pivot]
    mid   = [x for x in A if x == pivot]
    right = [x for x in A if x > pivot]
    return rand_quicksort(left) + mid + rand_quicksort(right)
# Expected O(n log n) untuk SEMUA input

Monte Carlo - Selalu cepat, mungkin salah

Selalu selesai dalam waktu tertentu, tapi ada kemungkinan kecil hasilnya salah. Contoh: Miller-Rabin primality test - mungkin salah dengan probabilitas ≤ 2^(-k) untuk k iterasi. Dipakai di kriptografi RSA.

Randomized QuickSort: pivot acak membuat adversary tidak bisa buat input kasus terburuk. Expected depth rekursi = O(log n) untuk semua input, tidak hanya data acak.
BAGIAN 3 · [MODERN] PENCARIAN VEKTOR SKALA BESAR

LSH dan HNSW - approximate nearest neighbor di AI

Sistem RAG, rekomendasi, dan semantic search perlu mencari vektor paling mirip dari miliaran vektor. Exact search = O(n·d) - mustahil. Perlu aproksimasi:

LSH (Locality-Sensitive Hashing)

Vektor yang mirip di-hash ke bucket yang sama dengan probabilitas tinggi. Cari hanya dalam bucket → sublinear time. Trade-off: recall tidak 100% - beberapa tetangga dekat mungkin terlewat.

HNSW (Hierarchical Navigable Small World)

Graf berlapis: layer atas = koneksi jauh, layer bawah = koneksi dekat. Navigasi dari layer atas ke bawah. Kompleksitas: O(log n) per query. Dipakai di FAISS (Facebook), Pinecone, Weaviate.

MetodeKompleksitas queryRecall
Exact (brute force)O(n·d)100%
LSHO(n^ρ·d)~90-95%
HNSWO(log n)~95-99%
IVF (FAISS)O(√n·d)~90-98%
Analogi HNSW - peta bertingkat. Layer 0 = jalan setapak (detil). Layer 1 = jalan raya. Layer 2 = jalan tol. Navigasi: masuk dari tol (kasar), turun ke jalan raya, lalu setapak. Jauh lebih cepat dari jalan setapak dari awal.
BAGIAN 4 · [MODERN] COMPLEXITY OF TRANSFORMERS

Self-Attention O(n²) dan cara mengatasinya

Self-attention: tiap token harus "kenalan" dengan semua token lain → O(n²) untuk n token. Ini bottleneck untuk context window panjang.

Standard attention: O(n²d) waktu, O(n²) memori
n=2.000: 4 juta entry → OK
n=32.000: 1 miliar entry → berat
n=128.000: 16 miliar entry → sangat berat

FlashAttention (2022)

Tetap O(n²d) secara waktu, tapi O(n) memori dengan IO-aware tiling. Membaca/tulis HBM lebih sedikit → 2-4× lebih cepat di GPU. Hasilnya identik dengan standard attention - bukan aproksimasi!

Sparse/Linear Attention

Kurangi kompleksitas ke O(n log n) atau O(n) dengan hanya menghitung sebagian pasangan. Trade-off: akurasi turun sedikit. Contoh: Longformer (sliding window), BigBird (random + global).

KUNCI JAWABAN

Kunci Aproksimasi, Randomized, Skala Besar

1

Setiap edge (u,v) yang dipilih algoritma masuk ke matching M. OPT harus menutup setiap edge di M → OPT ≥ |M|. Algoritma menambahkan 2 vertex per edge → hasilnya = 2|M| ≤ 2·OPT. Rasio ≤ 2. ✓

2

Average case: rata-rata atas semua input (asumsi distribusi tertentu). Expected case: rata-rata atas pilihan random algoritma, untuk satu input tetap. Randomized QS: expected O(n log n) untuk setiap input tetap karena probabilitas pivot bagus tinggi terlepas dari isi data.

3

128K/4K = 32× lebih panjang. Biaya attention: (32)² = 1024× lebih mahal. FlashAttention mempertahankan kompleksitas O(n²) tapi mengurangi akses memori GPU (IO-aware) → 2-4× lebih cepat dalam wall-clock. Batasnya: tetap O(n²) secara teori - untuk n sangat panjang butuh sparse/linear attention.

4

HNSW: O(log n) query, recall ~95-99%. Exact: O(n·d), recall 100%. Pilih exact saat: (1) n kecil (<10.000), (2) recall 100% kritis (keamanan, hukum), (3) d kecil. Pilih HNSW saat: skala jutaan-miliaran vektor, latensi real-time penting.

5

Input terurut + pivot terakhir → O(n²). Random pivot → expected O(n log n). Rasio waktu pada n=10.000: naif ≈ 100 juta operasi, random ≈ 130 ribu operasi → ~750× lebih cepat. Rasio empiris biasanya 100-1000× untuk input terurut.
