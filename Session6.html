KERANGKA TEORI · 5W1H - Struktur Data Efisien

Kenapa materi ini ada, untuk siapa, dan bagaimana memakainya?

What - Apa?

Struktur data menentukan bagaimana data diorganisir sehingga operasi tertentu efisien. Heap untuk priority queue O(log n), Hash Table untuk lookup O(1) rata-rata, Balanced BST untuk operasi terurut O(log n), Bloom Filter untuk membership probabilistik O(k). Pilihan struktur data menentukan setengah kompleksitas algoritma.

Why - Mengapa?

Algoritma terbaik pun bisa lambat jika struktur datanya salah. Dijkstra dengan array biasa O(V²) vs dengan min-heap O(E log V) - pada graf sparse itu bisa 1000× lebih cepat. Hash Table membuat operasi O(n) jadi O(1) rata-rata. Bloom Filter menghemat 90% memori untuk membership check di CDN dan database.

Who - Siapa?

Backend developer (cache = hash table, event queue = heap), sistem engineer (database index = B-tree), ML engineer (priority beam search = heap), data engineer (approximate counting = Count-Min Sketch), security engineer (Bloom filter di firewall dan CDN), dan semua programmer yang butuh operasi efisien di skala produksi.

When - Kapan?

Heap: perlu ambil min/max berulang (Dijkstra, Prim, task scheduler, K largest). Hash Table: lookup/insert/delete O(1) dan urutan tidak penting. BST: butuh terurut sekaligus efisien (range query, predecessor). Bloom Filter: memori terbatas dan false positive bisa ditoleransi - misal cek apakah URL sudah dikunjungi crawler.

Where - Di mana?

Heap di Python: heapq, Java: PriorityQueue. Hash di Python: dict/set (O(1) avg). BST di Python: sortedcontainers.SortedList. Bloom Filter di: Redis, Cassandra, CDN edge servers, Bitcoin SPV. Count-Min Sketch di: streaming analytics, Cloudflare DDoS detection, network traffic monitoring secara real-time.

How - Bagaimana?

Heap: array di mana parent ≤ children (min-heap). Insert = O(log n) sift-up, extract-min = O(log n) sift-down, build dari array = O(n) amortized. Hash: key → hash function → bucket, collision via chaining atau open addressing, load factor dijaga di bawah 0.75. Analisis amortized: dynamic array doubling - total cost n insert = O(n), per insert = O(1).

PETA LANGKAH · KENAPA PENTING

Peta langkah: memilih struktur data yang tepat

1. Lihat operasi yang sering
Apakah lebih sering insert, search, atau mengambil nilai minimum? Pilih struktur yang optimal untuk operasi itu.
2. Bandingkan kompleksitas
Heap untuk priority queue, hash table untuk akses rata-rata O(1), balanced BST untuk urutan dan O(log n) terjamin.
3. Perhatikan rata-rata vs terburuk
Hash table O(1) hanya rata-rata. Dengan banyak collision, operasinya bisa menjadi O(n).
4. Gunakan amortisasi
Beberapa operasi sesekali mahal, misalnya resize array. Analisis amortisasi menghitung biaya rata-rata serangkaian operasi.
5. Pertimbangkan memori
Untuk data sangat besar, struktur probabilistik seperti Bloom filter menukar sedikit akurasi dengan memori yang jauh lebih kecil.
Kenapa penting: Sering kali mengganti struktur data memberi perbaikan lebih besar daripada mengubah algoritma. Ini juga dasar bagi algoritma greedy dan Dijkstra di materi berikutnya.
Jangan hanya melihat notasi Big-O. Perhatikan juga apakah itu rata-rata atau terburuk, dan berapa besar konstanta serta memorinya.
BAGIAN 1 · HEAP

Heap - Struktur data untuk priority queue

import heapq
# Min-Heap di Python
h = []
heapq.heappush(h, 5)   # O(log n)
heapq.heappush(h, 2)
heapq.heappush(h, 8)
heapq.heapify([4,1,7,3])  # Build: O(n) !
x = heapq.heappop(h)   # Extract-min O(log n)
# Heap sort: O(n log n)
def heapsort(arr):
    h = arr[:]
    heapq.heapify(h)   # O(n)
    return [heapq.heappop(h)  # O(n log n)
            for _ in range(len(h))]
Build Heap O(n): Walaupun terlihat seperti O(n log n), analisis amortized membuktikan heapify dari bawah ke atas hanya O(n). Ini bukan sihir - sebagian besar node ada di level bawah dengan sedikit pekerjaan.

Analogi: Heap seperti turnamen tenis. Juara duduk di atas, pemenang babak pertama di bawahnya. Untuk temukan juara: lihat akar O(1). Untuk hapus juara: promosikan runner-up, atur ulang O(log n).

Digunakan di: Dijkstra shortest path (priority queue), event simulation, OS scheduler, median finder (dua heap).

BAGIAN 2 · HASH TABLE

Hash Table - O(1) rata-rata untuk insert & search

Hash table memetakan kunci ke indeks via fungsi hash h(k). Collision terjadi ketika h(k₁) = h(k₂) untuk k₁ ≠ k₂.

Chaining: tiap slot menyimpan linked list. Worst case O(n) jika semua ke slot yang sama.

Open Addressing: probe slot berikutnya (linear, quadratic, double hashing). Load factor α < 0.7 untuk performa baik.

Load factor α = n/m (n=elemen, m=slot). Jika α > 0.7–0.8, resize (double the table) - O(n) sekali, tapi amortized O(1).

Balanced BST - O(log n) terjamin untuk semua operasi

StrukturInsertSearchDeleteMin/Max

BST yang tidak seimbang: Insert 1,2,3,4,5 secara berurutan → pohon degenerasi ke linked list! Semua operasi jadi O(n). AVL/Red-Black rebalance otomatis setelah setiap operasi.
Analogi AVL: Seperti timbangan yang selalu disetarakan. Setiap kali satu sisi terlalu berat (tinggi selisih >1), lakukan rotasi. Rotasi O(1), tapi terjamin pohon tetap O(log n) tinggi.

AVL invariant: Untuk setiap node, |tinggi(kiri) − tinggi(kanan)| ≤ 1. Tinggi maksimal = 1.44 log₂(n+2). Rotasi kiri/kanan/kiri-kanan/kanan-kiri.

Python: from sortedcontainers import SortedList - implementasi BST yang sangat cepat. bisect module untuk binary search pada list terurut.

Cara membaca rumus:
• O(log n) untuk AVL dan Red-Black: tinggi pohon dijaga sekitar log₂n, sehingga tiap operasi hanya menelusuri jalur itu.
• O(n) pada BST biasa: pohon bisa berubah menjadi daftar berantai, sehingga tinggi pohon menjadi n.
BAGIAN 4 · ANALISIS AMORTIZED

Amortized Analysis - biaya rata-rata serangkaian operasi

class DynamicArray:
    def __init__(self):
        self.cap = 1
        self.size = 0
        self.data = [None]
    def append(self, x):    # O(1) amortized!
        if self.size == self.cap:
            # Resize: copy semua elemen
            self.cap *= 2   # double!
            new = [None]*self.cap
            for i in range(self.size):
                new[i] = self.data[i]
            self.data = new
        self.data[self.size] = x
        self.size += 1
# Total cost n appends:
# resize di 1,2,4,8,...
# = 1+2+4+...+n = 2n = O(n)
# Per operasi: O(n)/n = O(1) amortized
Intuisi bank account: Setiap append "menabung" 2 kredit. Saat resize, semua kredit tabungan membayar copy. Jadi setiap append: O(1) amortized meskipun sesekali O(n).
Analogi: Jalan tol dengan tarif flat vs bayar per km. Flat lebih mudah dihitung, meskipun sesekali perjalanan panjang. Amortized analysis = tarif flat untuk serangkaian operasi.
OperasiWorst caseAmortized
list.append()O(n)O(1)
dict insertO(n) resizeO(1)
Splay tree findO(n)O(log n)
Cara membaca rumus:
• Biaya amortisasi = total biaya serangkaian operasi ÷ jumlah operasi.
• Pada append: biaya satu operasi bisa O(n) saat resize, tetapi total n operasi tetap O(n), sehingga rata-rata O(1).
MODERN · BLOOM FILTER & COUNT-MIN SKETCH

Struktur Probabilistik - Space-efficient untuk Big Data

Bloom Filter: Array bit + k fungsi hash. Insert: set k bit. Query: cek k bit. False positive mungkin (jawab "ada" padahal tidak), tapi false negative tidak pernah ("tidak ada" selalu benar).

Kompleksitas: O(k) insert dan query, O(m) space (m = ukuran array bit). False positive rate ≈ (1−e^(−kn/m))^k.

Digunakan di: Google Bigtable (cek apakah baris ada), PostgreSQL (join acceleration), browser malicious URL check, Redis, Cassandra.

Count-Min Sketch: Grid d×w dengan d hash functions. Insert: increment d sel. Query: ambil minimum dari d sel. Overestimate mungkin, tapi tidak pernah underestimate.

Digunakan di: Twitter trending topics, network traffic monitoring, frekuensi kata di stream data besar. Space: O(d×w), jauh lebih kecil dari menyimpan semua elemen.
StrukturSpaceErrorFalse Neg?
Hash SetO(n)0%Tidak
Bloom FilterO(m) << nFP: εTidak
Count-MinO(d·w)OverestimateTidak
Cara membaca rumus:
• O(k): setiap insert dan query menyentuh k bit (k = jumlah fungsi hash).
• O(m): ruang yang dipakai, dengan m = ukuran array bit.
• Probabilitas false positive ≈ (1 − e^(−kn/m))ᵏ, dengan n = jumlah elemen yang dimasukkan.
INTERAKTIF · HASH TABLE COLLISION

Lihat efek load factor pada collision rate

Simulasi Hash Table Collision
Load factor α = n/m. Semakin tinggi α, semakin besar probabilitas collision. Untuk chaining: E[panjang chain] = α. Untuk open addressing: butuh α < 1 agar ada slot kosong.
Birthday paradox: Dengan m=365 hari dan n=23 orang, P(collision) > 50%! Hash table menghadapi masalah yang sama. Solusi: tabel lebih besar atau hash function yang baik.

Aturan praktis: Python dict mulai resize saat load factor > 0.67. Java HashMap threshold 0.75. Redis hash table 1.0 (chaining).

Cara membaca rumus:
• α = n/m: load factor, yaitu jumlah elemen dibagi ukuran tabel.
• Chaining: rata-rata panjang rantai = α. Semakin besar α, semakin lambat pencarian.
• Open addressing: butuh α < 1 agar masih ada slot kosong.

KUNCI JAWABAN

Kunci Struktur Data Efisien

1

Node di level h (dari bawah) butuh sift-down max h langkah. Jumlah node level h = n/2^h. Total = Σ h·n/2^h = n·Σ h/2^h = n·2 = O(n). Sebagian besar node di level bawah dengan sedikit pekerjaan mengimbangi node atas.

2

"alice" (5 huruf): 5 mod 7 = 5. "bob" (3): 3 mod 7 = 3. "carol" (5): 5 mod 7 = 5 → collision! Chaining: slot 5 berisi linked list ["alice", "carol"]. Search "carol": hash→5, traverse list hingga ketemu.

3

Resize di n=1,2,4,8: copy 1+2+4+8=15 elemen. Total cost 8 append + 15 copy = 23. Per operasi: 23/8 ≈ 2.9 = O(1). Formula: total cost ≤ 3n → amortized O(1) per append.

4

FP rate ≈ (1−e^(−3×5/20))^3 = (1−e^(−0.75))^3 ≈ (0.528)^3 ≈ 0.147 ≈ 14.7%. Semakin besar m: FP rate turun, tapi space naik. Trade-off: sesuaikan berdasarkan toleransi false positive yang bisa diterima.

5

BST lebih baik: (1) Perlu urutan data - BST support in-order traversal O(n), hash table tidak. (2) Perlu range query (semua key antara A dan B) - BST O(log n + k) di mana k=hasil, hash table O(n). Hash table unggul untuk random access O(1).
