Branch and Bound

Backtracking dengan senjata tambahan: bounding function. Kalau batas atas solusi terbaik dari cabang ini sudah lebih buruk dari solusi terbaik yang sudah ditemukan - potong cabang itu sekarang.

PETA LANGKAH · KENAPA PENTING

Peta langkah: Branch and Bound

1. Branch
Pecah masalah menjadi subproblem, misalnya dengan memutuskan apakah suatu item diambil atau tidak.
2. Bound
Hitung batas untuk tiap cabang. Pada maksimasi, ini batas atas nilai yang mungkin dicapai cabang itu.
3. Prune
Jika batas cabang tidak lebih baik dari solusi terbaik yang sudah ditemukan, buang cabang itu.
4. Perbarui solusi terbaik
Setiap kali menemukan solusi lengkap yang lebih baik, simpan sebagai batas baru.
5. Bandingkan dengan backtracking
Backtracking hanya memangkas cabang yang tidak valid. B&B juga memangkas cabang yang tidak mungkin lebih baik.
Kenapa penting: B&B menjamin solusi optimal sambil memangkas sebanyak mungkin pencarian. Solver industri untuk logistik dan penjadwalan memakai prinsip ini.
Kualitas batas menentukan kecepatan. Batas yang longgar membuat banyak cabang tidak terpangkas, dan B&B bisa tetap eksponensial.
BAGIAN 1 · PRINSIP B&B

Branch = pecah masalah, Bound = hitung batas

Branch and Bound adalah enumerasi sistematis dengan dua mekanisme pemangkasan:

1. Branching - Pecah node menjadi submasalah (seperti backtracking).

2. Bounding - Hitung batas (atas untuk maksimasi, bawah untuk minimasi) dari solusi terbaik yang bisa dicapai dari node ini.

3. Pruning - Kalau bound lebih buruk dari incumbent (solusi terbaik saat ini), buang seluruh subtree.

Analogi - lelang properti. Kamu mau beli properti dengan anggaran 500 juta. Agen tahu harga minimum daerah A adalah 600 juta → langsung skip daerah A tanpa lihat-lihat. Ini bounding: tanpa perlu jelajah semua unit di A, kita tahu tidak ada yang terjangkau.

BAGIAN 2 · KNAPSACK B&B

0/1 Knapsack dengan Branch and Bound - kodenya

Urutkan item berdasarkan rasio nilai/berat. Upper bound = nilai saat ini + relaksasi fraksional sisa item (ambil item sebagian jika perlu memenuhi kapasitas).

import heapq
def knapsack_bnb(weights, values, W):
    items = sorted(zip(values, weights),
                   key=lambda x: x[0]/x[1], reverse=True)
    best = 0
    # state: (−ub, level, current_val, current_wt)
    pq = [(-upper_bound(items,0,0,0,W), 0, 0, 0)]
    while pq:
        neg_ub, lv, cv, cw = heapq.heappop(pq)
        if -neg_ub <= best: continue   # prune!
        if lv == len(items):
            best = max(best, cv); continue
        # branch: ambil item lv
        nw = cw + items[lv][1]
        if nw <= W:
            nv = cv + items[lv][0]; best = max(best, nv)
            ub = upper_bound(items, lv+1, nv, nw, W)
            if ub > best: heapq.heappush(pq, (-ub, lv+1, nv, nw))
        # branch: skip item lv
        ub = upper_bound(items, lv+1, cv, cw, W)
        if ub > best: heapq.heappush(pq, (-ub, lv+1, cv, cw))
    return best

Cara membaca rumus:
• Upper bound = nilai saat ini + nilai relaksasi fraksional sisa kapasitas.
• Relaksasi fraksional: item boleh diambil sebagian, sehingga batasnya selalu lebih longgar tetapi valid.
• Jika upper bound ≤ solusi terbaik yang sudah ditemukan, cabang ini dipangkas.
Perhatikan log-nya: setiap baris "prune" adalah satu cabang pohon yang tidak perlu dijelajahi. Semakin cepat solusi bagus ditemukan, semakin tinggi nilai best, dan semakin banyak cabang yang dipangkas.
BAGIAN 3 · [MODERN] B&B DI INDUSTRI

Integer Linear Programming - B&B di balik solver industri

Masalah optimasi kombinatorial skala besar di industri diselesaikan dengan solver ILP/MIP (Mixed Integer Programming) yang menggunakan B&B sebagai fondasi.

Gurobi / CPLEX / SCIP

Solver komersial/open-source yang mengkombinasikan B&B dengan LP relaxation sebagai bound, cutting planes untuk memperketat bound, dan heuristik untuk menemukan incumbent awal. Menyelesaikan masalah dengan jutaan variabel.

Google OR-Tools (CP-SAT)

Open-source, dipakai di Google Maps routing, scheduling. Kombinasi SAT solver + propagasi constraint + B&B. Bisa menyelesaikan TSP 1000 kota atau jadwal 10.000 karyawan.

Analogi - paket logistik. JNE/Gojek harus alokasikan ribuan paket ke ratusan kurir dengan minimasi biaya. Ini adalah Vehicle Routing Problem - bentuk TSP yang diperluas. Tanpa solver ILP, tidak mungkin diselesaikan secara optimal; dengan OR-Tools + B&B, bisa dalam hitungan menit.

Bedah Rumus 1/3 · Langkah 1: cara membaca

Aturan pangkas (pruning rule)

Maksimasi: pangkas simpul jika UB(node) ≤ best;    Minimasi: pangkas jika LB(node) ≥ best

Cara membaca rumus ini

“Untuk masalah maksimasi, pangkas simpul jika batas atasnya tidak lebih besar dari solusi terbaik yang sudah ditemukan. Untuk minimasi, pangkas jika batas bawahnya tidak lebih kecil dari solusi terbaik.”
1

UB (upper bound)

nilai paling optimis yang MUNGKIN dicapai dari cabang ini.

2

best (incumbent)

solusi valid terbaik yang sudah ditemukan sejauh ini.

3

UB ≤ best

sebaik-baiknya cabang ini tidak akan mengalahkan best → buang.

Arti tiap simbol

UB / LBbatas atas / batas bawah cabang
bestincumbent: solusi terbaik sementara
nodesimpul pohon = keputusan sebagian
Intuisinya: Kita tidak perlu menjelajahi cabang untuk tahu cabang itu kalah. Batas yang optimis tetapi valid sudah cukup sebagai bukti.

Bedah Rumus 1/3 · Langkah 3: dari hitungan ke kode & kasus nyata

Mengapa solusi awal yang bagus mempercepat B&B

Implementasi di proyek nyata

Solver industri (Gurobi, CPLEX, OR-Tools) menjalankan heuristik primal di awal untuk mendapatkan incumbent yang bagus, karena rumus pangkas ini membuat incumbent bagus = pohon pencarian kecil.

Contoh lain di kasus ini

1

best = 0 di awal

hampir tidak ada yang bisa dipangkas.

2

Heuristik greedy cepat → best = 200

semua cabang dengan UB ≤ 200 langsung dibuang.

3

Cabang UB = 230

tetap dijelajahi; jika menghasilkan 220, best naik lagi.

4

Efek

best naik → pruning makin agresif → pohon makin kecil.

Kode Python

def bnb(node, best):
    if upper_bound(node) <= best:      # aturan pangkas (maksimasi)
        return best
    if is_leaf(node):
        return max(best, value(node))
    for child in branch(node):          # telusuri anak yang paling menjanjikan dulu
        best = bnb(child, best)
    return best

Memilih proyek investasi dengan anggaran tetap

Implementasi di proyek nyata

Pemilihan portofolio proyek (capital budgeting), pemilihan fitur dengan biaya pengembangan, dan pengisian kargo pesawat. Pola umumnya: longgarkan satu syarat yang sulit (integer) agar batas mudah dihitung.

Contoh lain di kasus ini

1

Item terurut rasio (v, w)

(40,2) r=20, (30,5) r=6, (50,10) r=5, (10,5) r=2; W = 16.

2

Akar

40 + 30 = 70, sisa 9 → 9 × 5 = 45 → UB = 115.

3

Cabang “tanpa item 1”

30 + 50 = 80, sisa 1 → 1 × 2 = 2 → UB = 82.

4

Jika best = 90 sudah ditemukan

cabang tanpa item 1 (UB 82) langsung dipangkas.

Kode Python

def upper_bound(items, i, val, wt, W):   # items terurut v/w menurun
    ub, cap = val, W - wt
    while i < len(items) and items[i][1] <= cap:
        ub += items[i][0]; cap -= items[i][1]; i += 1
    if i < len(items):
        ub += cap * items[i][0] / items[i][1]   # ambil sebagian
    return ub

print(upper_bound([(40,2),(30,5),(50,10),(10,5)], 0, 0, 0, 16))  # 115.0

Integer Linear Programming dan MIP gap

maks cTx  s.t.  Ax ≤ b,  x ∈ ℤn;    gap = (UB − LB) / UB

Cara membaca rumus ini

“Maksimalkan c transpos x dengan syarat A x kurang dari sama dengan b dan x bilangan bulat. Gap adalah selisih batas atas dan batas bawah dibagi batas atas.”
1

cᵀx

fungsi tujuan: jumlah cᵢ·xᵢ (keuntungan total).

2

Ax ≤ b

kumpulan batasan linear (anggaran, kapasitas, jam kerja).

3

x ∈ ℤⁿ

variabel harus bilangan bulat - inilah yang membuatnya NP-hard.

4

gap

UB dari relaksasi LP, LB dari solusi bulat terbaik; gap 0 = terbukti optimal.

Arti tiap simbol

ckoefisien keuntungan/biaya
A, bmatriks dan batas kanan batasan

Intuisinya: Tanpa syarat bulat, LP bisa diselesaikan cepat. Solver ILP memakai LP relaksasi sebagai bound di setiap simpul B&B, lalu bercabang pada variabel yang hasilnya pecahan (x = 2,6 → cabang x ≤ 2 dan x ≥ 3).

Penjadwalan shift dan rute armada

Implementasi di proyek nyata

Maskapai menjadwalkan kru, perusahaan logistik menyusun rute armada, rumah sakit menyusun shift perawat - semuanya ILP berukuran ribuan sampai jutaan variabel yang diselesaikan dengan Gurobi, CPLEX, HiGHS, atau OR-Tools. Log solver selalu menampilkan kolom “Gap”.

KUNCI JAWABAN

Kunci Branch and Bound

1

Bounding function longgar → bound hampir tidak pernah di bawah incumbent → hampir tidak ada pruning → B&B ≈ brute force. Bound ketat = banyak pruning = B&B jauh lebih cepat. Tradeoff: bound ketat biasanya lebih mahal dihitung.

2

Relaksasi fraksional (fractional knapsack) selalu memberikan nilai ≥ optimal 0/1 knapsack - karena kita "boleh" ambil sebagian item. Jadi ini valid sebagai upper bound (tidak pernah underestimate). Setiap solusi 0/1 feasible adalah subset dari solusi fraksional.

3

B&B lebih unggul saat bound mengidentifikasi banyak suboptimal node. B&B bisa lebih lambat kalau: (1) solusi optimal ada di cabang pertama yang dieksplorasi (incumbent langsung bagus, tapi B&B tetap jelajah sebelum yakin), atau (2) biaya hitung bound tinggi tapi pruning sedikit.

4

Reduced cost matrix: kurangi min tiap baris dan kolom. Jumlah pengurangan = lower bound biaya TSP. Biaya komputasi: O(n²) per node. Untuk n=5: matrix 5×5, O(25) per node - sangat murah dibanding menjelajah O(n!) cabang.

5

Untuk 5 item: backtracking tanpa bound = 2^5 = 32 node (semua kombinasi). B&B dengan upper bound fraksional biasanya menjelajah 10-15 node, prune sisanya. Efisiensi meningkat drastis saat n membesar.
