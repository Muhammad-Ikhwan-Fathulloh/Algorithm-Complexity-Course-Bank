KERANGKA TEORI · 5W1H - Greedy II (Graf) dan A*

Kenapa materi ini ada, untuk siapa, dan bagaimana memakainya?

What - Apa?

Greedy di graf: Kruskal dan Prim mencari Minimum Spanning Tree (MST). Dijkstra mencari jalur terpendek single-source berbobot positif. Huffman Coding membangun kode prefix-free optimal untuk kompresi data. A* menggabungkan Dijkstra dengan heuristik untuk menemukan jalur ke goal lebih cepat.

Why - Mengapa?

Infrastruktur jaringan (internet, jalan raya, pipa gas) semua butuh MST dan shortest path. Huffman langsung dipakai di gzip dan PNG yang kita pakai setiap hari. A* adalah backbone GPS navigation dan robot pathfinding. Memahami O(E log V) vs O(V²) menentukan apakah sistem bisa real-time.

Who - Siapa?

Network engineer (MST untuk desain jaringan minimum-cost), game developer (A* untuk NPC pathfinding di Unity/Unreal), developer GPS/maps (Dijkstra/A* untuk routing), data compression engineer (Huffman untuk codec), dan siapapun yang membangun sistem yang butuh jalur optimal di graf berbobot positif.

When - Kapan?

Kruskal: graf sparse, gunakan union-find O(E log E). Prim: graf dense, gunakan min-heap O(E log V). Dijkstra: shortest path, bobot non-negatif, satu sumber. A*: shortest path ke satu goal spesifik dengan heuristik tersedia. Huffman: kompresi data statis di mana frekuensi simbol diketahui sebelumnya.

Where - Di mana?

Kruskal/Prim di: desain kabel jaringan, dendogram clustering (single-linkage). Dijkstra di: OSPF routing protocol, database query planning. A* di: game engine Unity NavMesh, robot motion planning, puzzle AI solver. Huffman di: gzip, DEFLATE, PNG lossless, JPEG DC coefficients. Semua tersedia di library NetworkX Python.

How - Bagaimana?

Kruskal: sort semua edge by weight, pakai Union-Find untuk skip cycle, O(E log E). Prim: grow MST dari satu node, min-heap untuk selalu ambil edge terkecil ke node belum dikunjungi, O(E log V). Dijkstra: priority queue dengan dist[v], relax edges. A*: f(n) = g(n) + h(n), heuristik h harus admissible - tidak pernah overestimate jarak ke goal.

PETA LANGKAH · KENAPA PENTING

Peta langkah: MST, shortest path, dan A*

1. Kruskal
Urutkan semua sisi dari yang paling murah. Tambahkan sisi selama tidak membentuk siklus (pakai Union-Find).
2. Prim
Mulai dari satu simpul, lalu selalu tambahkan sisi termurah yang menghubungkan ke simpul baru.
3. Dijkstra
Relaksasi jarak tetangga dengan priority queue. Syaratnya: semua bobot sisi tidak negatif.
4. A*
Tambahkan heuristik h(n) yang tidak melebih-lebihkan jarak sebenarnya (admissible). Eksplorasi jadi lebih terarah.
5. Bandingkan
Hitung kompleksitas dan jumlah simpul yang dikunjungi. A* menang bila heuristiknya bagus.
Kenapa penting: Pola ini dipakai di peta, routing jaringan, dan pathfinding game. Memahami kapan greedy pada graf benar akan membantu di materi selanjutnya.
Heuristik harus admissible agar A* menjamin jalur optimal. Heuristik yang terlalu besar mempercepat tetapi bisa menghasilkan jalur yang salah.
BAGIAN 1 · MINIMUM SPANNING TREE

Kruskal vs Prim - Dua cara greedy untuk MST

Kruskal: Sort semua edge by weight, tambahkan edge terkecil yang tidak membentuk cycle (union-find). O(E log E).

def kruskal(n, edges):
    edges.sort(key=lambda e: e[2])
    parent = list(range(n))
    def find(x):
        if parent[x]!=x: parent[x]=find(parent[x])
        return parent[x]
    def union(a,b):
        parent[find(a)] = find(b)
    mst = []
    for u, v, w in edges:
        if find(u) != find(v):
            union(u, v); mst.append((u,v,w))
    return mst

Prim: Tumbuh dari satu node, selalu tambahkan edge terkecil ke node baru. Priority queue. O(E log V).

AspekKruskalPrim
PendekatanGlobal (sort edge)Lokal (tumbuh)
KompleksitasO(E log E)O(E log V)

Kruskal: Pilih jalan termurah dari semua jalan yang ada, asal tidak membentuk loop. Prim: Dari kota yang sudah terjangkau, ekspansi ke kota terdekat berikutnya.
BAGIAN 2 · DIJKSTRA

Dijkstra - Shortest path dengan priority queue

import heapq
def dijkstra(graph, src):
    # graph[u] = [(v, weight), ...]
    dist = {v: float('inf') for v in graph}
    dist[src] = 0
    pq = [(0, src)]   # (distance, node)
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]: continue  # sudah lebih baik
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(pq, (dist[v], v))
    return dist
# O(E log V) dengan binary heap
Syarat: Semua bobot edge harus ≥ 0. Untuk edge negatif, gunakan Bellman-Ford. Dijkstra dengan edge negatif bisa memberikan hasil salah!
Mengapa greedy benar? Ketika node u di-extract dari priority queue, dist[u] sudah final - tidak ada jalur lebih pendek yang mungkin (semua edge non-negatif). Ini adalah invariant greedy Dijkstra.
AlgoritmaKompleksitasEdge negatif?
DijkstraO(E log V)✗ Tidak
Bellman-FordO(VE)✓ Ya
Floyd-WarshallO(V³)✓ (no neg cycle)
A*O(E log V) + h✗ Tidak
Analogi: Peta GPS Dijkstra: dari kota asal, selalu kunjungi kota yang sudah diketahui paling dekat lebih dulu. Expand semua arah sama rata. A* akan menambah "intuisi arah" ke tujuan.
BAGIAN 3 · HUFFMAN CODING

Huffman - Prefix-free encoding optimal

import heapq
def huffman(freq):
    # freq = {'a':5, 'b':9, 'c':12, ...}
    heap = [[f, [ch, ""]]
            for ch, f in freq.items()]
    heapq.heapify(heap)
    while len(heap) > 1:
        lo = heapq.heappop(heap)  # dua terkecil
        hi = heapq.heappop(heap)
        for p in lo[1:]: p[1] = '0' + p[1]
        for p in hi[1:]: p[1] = '1' + p[1]
        heapq.heappush(heap, [lo[0]+hi[0]]
                             + lo[1:] + hi[1:])
    return sorted(heap[0][1:], key=lambda x:x[1])
# O(n log n)
Huffman optimal: Menghasilkan prefix-free code dengan total panjang bit minimum. Karakter sering = kode pendek, karakter jarang = kode panjang. Digunakan di DEFLATE (zip, gzip, PNG).

Huffman: 2.24 bit/karakter rata-rata vs 3 bit fixed → penghematan 25%!

Cara membaca rumus:
• Rata-rata bit = Σ (frekuensi × panjang kode). Contoh: 0,45·1 + 0,13·3 + … ≈ 2,24 bit per karakter.
• Fixed 3 bit: 3 bit untuk setiap karakter, jadi penghematannya (3 − 2,24)/3 ≈ 25%.
BAGIAN 4 · A* SEARCH

A* - Dijkstra dengan heuristik

import heapq
def astar(graph, start, goal, h):
    # h(n) = heuristic: estimasi jarak n ke goal
    open_set = [(h(start), 0, start, [])]
    visited = set()
    while open_set:
        f, g, u, path = heapq.heappop(open_set)
        if u in visited: continue
        visited.add(u); path = path + [u]
        if u == goal: return path, g
        for v, w in graph[u]:
            if v not in visited:
                new_g = g + w
                heapq.heappush(open_set,
                    (new_g + h(v), new_g, v, path))
    return None, float('inf')
# h(n) = Manhattan distance untuk grid
f(n) = g(n) + h(n): g(n) = biaya aktual dari start ke n. h(n) = estimasi biaya dari n ke goal. A* mengeksplorasi node dengan f terkecil dulu.

Admissible heuristic: h(n) ≤ true cost ke goal. Menjamin A* menemukan jalur optimal. Manhattan distance admissible untuk grid (tidak ada diagonal).

Consistent heuristic: h(n) ≤ w(n,n') + h(n'). Lebih kuat dari admissible - menjamin setiap node hanya dikunjungi sekali.

A* vs Dijkstra: Dijkstra = mencari kunci di seluruh rumah secara sistematis. A* = mencari kunci tapi tahu kira-kira di mana ("biasanya di meja"), jadi cek meja dulu. Lebih cepat dengan pengetahuan ekstra.
Cara membaca rumus:
• f(n) = g(n) + h(n): g = biaya aktual dari start ke n, h = estimasi sisa biaya ke goal.
• Admissible: h(n) ≤ biaya sebenarnya ke goal. Ini menjamin jalur optimal.
• Consistent: h(n) ≤ w(n,n′) + h(n′) untuk setiap sisi. Menjamin tiap simpul dikunjungi sekali.

KUNCI JAWABAN

Kunci Greedy II dan A*

1

Kruskal: proses edge global (sort by weight, union-find), cocok graf sparse (E≈V). Prim: tumbuh dari satu node (priority queue), cocok graf dense (E≈V²). Kruskal O(E log E), Prim O(E log V) dengan heap - hampir sama untuk sparse, Prim lebih baik untuk dense.

2

Graf: A→B (w=1), A→C (w=10), B→C (w=-100). Dijkstra dari A: dist[C]=10 (via A→C). Tapi jalur A→B→C = 1+(-100)=-99 lebih pendek. Dijkstra tidak revisit C setelah menemukan dist=10.

3

Merge terkecil berulang: (E+F=14), (14+B=27), (C+D=28)... Rata-rata = (45×1 + 13×3 + 12×3 + 16×3 + 9×4 + 5×4)/100 = (45+39+36+48+36+20)/100 = 224/100 = 2.24 bit/karakter.

4

Admissible: h(n) ≤ true cost - tidak pernah overestimate. Consistent: h(n) ≤ c(n,n') + h(n') - segitiga. Contoh: h yang overestimates untuk beberapa node tapi underestimates rata-rata - admissible lokal tapi bisa inconsistent. Consistent → admissible, tapi admissible belum tentu consistent.

5

h=0: A* = Dijkstra (tidak ada panduan, eksplorasi seragam). h = true distance: A* langsung ke tujuan tanpa eksplorasi ekstra (optimal tapi butuh oracle). h > true distance (tidak admissible): A* mungkin tidak optimal - bisa melewatkan jalur terpendek karena terlalu yakin dengan estimasinya.
