KERANGKA TEORI · 5W1H - Brute Force dan Pencarian Ruang Keadaan

Kenapa materi ini ada, untuk siapa, dan bagaimana memakainya?

What - Apa?

Brute force = coba semua kemungkinan secara sistematis, pilih yang terbaik. Pencarian ruang keadaan = modelkan masalah sebagai graf state→goal, lalu cari jalur dengan BFS/DFS/IDDFS. Keduanya adalah fondasi sebelum teknik lebih canggih (greedy, DP, heuristik) diperkenalkan.

Why - Mengapa?

Setiap algoritma canggih butuh baseline yang jelas dan pasti benar. Brute force adalah baseline tersebut. Pencarian ruang keadaan adalah cara formal memecahkan masalah AI - perencanaan, game-playing, puzzle - semuanya bermula dari framework ini sebelum A* dan MCTS dikembangkan.

Who - Siapa?

Programmer yang baru mulai menyelesaikan masalah baru (brute force dulu sebagai verifikasi), peneliti AI yang merancang agent berbasis search, developer game yang butuh pathfinding, dan kandidat coding interview yang harus tahu kapan brute force cukup vs kapan perlu dioptimasi.

When - Kapan?

Brute force: saat n sangat kecil (n ≤ 15), butuh verifikasi solusi, atau sebagai langkah pertama sebelum optimasi. BFS: cari jalur terpendek di graf unweighted. DFS: topological sort, cycle detection. IDDFS: saat butuh optimalitas BFS dengan memori DFS.

Where - Di mana?

Brute force di: testing, kriptografi (key exhaustion), small-n optimization. BFS di: web crawling, social network shortest hop. DFS di: maze generation, compiler dependency resolution. IDDFS di: chess engine, puzzle solver AI. Semua dipakai langsung di library python-constraint, OpenAI Gym, dan game engine.

How - Bagaimana?

Brute force: generate semua kandidat → evaluasi → simpan terbaik. BFS: antrian FIFO, jelajah level per level, O(b^d) waktu + memori. DFS: stack LIFO, depth-first, O(b·d) memori. IDDFS: ulangi DFS dengan batas kedalaman naik 0,1,2,... - waktu O(b^d) memori O(b·d) seperti DFS, optimalitas seperti BFS.

BAGIAN A · PRINSIP BRUTE FORCE

Coba semua, pilih yang terbaik

Brute force = enumerasi semua solusi yang mungkin secara lengkap, lalu pilih yang optimal. Tidak ada trik, tidak ada heuristik.

Analogi - kode gembok 4 digit. Tidak tahu kombinasinya? Coba 0000, 0001, 0002 … sampai 9999. Pasti ketemu. Biaya: 10.000 percobaan = O(10ⁿ) untuk n digit. Besar, tapi pasti benar.

Kegunaan brute force:

SituasiKenapa cocok
n sangat kecil (n ≤ 10)Biaya terjangkau
Verifikasi algoritma lainHasil pasti benar
Baseline benchmarkPatokan kecepatan
Pertama kali menyelesaikan soal baruCepat dikode
Bahaya brute force: ukuran ruang pencarian bisa meledak. Selection sort O(n²) masih wajar untuk n=10.000, tapi TSP O(n!) untuk n=20 sudah mustahil seumur hidup.

Contoh sederhana: cari semua pasangan

def all_pairs(A):
    pairs = []
    for i in range(len(A)):         # O(n)
        for j in range(i+1,len(A)): # O(n)
            pairs.append((A[i],A[j]))
    return pairs  # → O(n²)
BAGIAN A · TSP BRUTE FORCE

Travelling Salesman Problem - O((n−1)!)

Diberikan n kota, cari rute terpendek yang mengunjungi semua kota tepat sekali dan kembali ke asal. Solusi brute force: coba semua permutasi kota (kecuali kota awal yang dikunci).

Jumlah rute = (n−1)!
n=5 → 24 rute      = cepat
n=10 → 362.880 rute  = masih OK
n=15 → 87 miliar rute = hitungan menit
n=20 → 1.2×10¹⁷ rute ≈ 3.800 tahun
n naik 1, biaya × n. Ini bukan O(n²) atau O(2ⁿ) - ini O(n!). Faktorial tumbuh lebih cepat dari eksponensial. Solusi eksaknya jadi mustahil untuk n ≥ 20.

BAGIAN B · PENCARIAN RUANG KEADAAN

Ruang keadaan: graf dari semua konfigurasi

Masalah seperti 8-puzzle, perencanaan robot, atau permainan bisa dimodelkan sebagai pencarian di ruang keadaan:

KomponenDi 8-puzzle
StatePosisi semua ubin (9! = 362.880 state unik)
Initial stateKonfigurasi awal
Goal stateUbin 1–8 urut, 0 di pojok
OperatorGeser ubin kosong: atas/bawah/kiri/kanan
CostJumlah langkah
Pencarian di ruang keadaan = graph traversal. BFS dan DFS dari mata kuliah struktur data langsung berlaku - dengan kompleksitas yang berbeda secara fundamental.
Analogi - labirin. State = posisimu sekarang. Operator = langkah ke kiri/kanan/atas/bawah. Goal = pintu keluar. Pertanyaannya: algoritma mana yang paling efisien menjelajahi labirin ini?

Kompleksitas pencarian: O(b^d)

b = branching factor (rata-rata operator yang valid per state). d = kedalaman solusi. Di 8-puzzle, b ≈ 3 dan d ≈ 20 → sekitar 3²⁰ ≈ 3.5 miliar state dalam kasus terburuk BFS. Di sinilah heuristik (A*) sangat membantu.

BAGIAN B · BFS

BFS - jaminan solusi terpendek, memori O(b^d)

BFS menjelajah level demi level. Dijamin menemukan solusi dengan jumlah langkah terkecil (optimal untuk uniform cost). Tapi menyimpan seluruh frontier dalam memori.

from collections import deque
def bfs(start, goal_fn, expand_fn):
    queue = deque([(start, [start])])
    seen = {start}
    while queue:
        state, path = queue.popleft()
        if goal_fn(state):
            return path           # ← solusi terpendek
        for nxt in expand_fn(state):
            if nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, path+[nxt]))
    return None  # tidak ada solusi
Kompleksitas: waktu O(b^d), memori O(b^d). Masalahnya di memori - pada d=20 dan b=3 butuh ~3.5 miliar entry.
Coba sendiri · BFS vs DFS di pohon kecil
Pilih BFS atau DFS untuk menjelajahi pohon 3-level (b=2).

Angka di setiap simpul = urutan kunjungan. BFS kunjungi level per level; DFS langsung terjun ke kedalaman.

BAGIAN B · DFS DAN IDDFS

DFS hemat memori - IDDFS ambil yang terbaik

DFS - waktu O(b^m), memori O(b·m)

Menjelajah cabang sedalam mungkin sebelum backtrack. Memori hanya menyimpan satu jalur aktif = O(b·m). Tapi tidak optimal - bisa menemukan solusi lebih dalam daripada yang terpendek. Dan bisa macet di loop tak terbatas kalau tidak ada pembatas kedalaman.

IDDFS (Iterative Deepening DFS) - waktu O(b^d), memori O(b·d)

Jalankan DFS dengan batas kedalaman 0, lalu 1, lalu 2, dst. Kalau batas d ketemu solusinya, selesai. Waktu seperti BFS (optimal), memori seperti DFS (linear). Ini yang biasanya dipakai di praktek AI tanpa heuristik.

MetodeWaktuMemoriOptimal?Lengkap?
BFSO(b^d)O(b^d)✓✓
DFSO(b^m)O(b·m)✗✗*
IDDFSO(b^d)O(b·d)✓✓
Analogi - baca buku. BFS = baca semua buku level-1 dulu, lalu level-2. DFS = baca satu buku sampai habis, lalu buku berikutnya. IDDFS = baca bab pertama semua buku, lalu bab dua semua buku, dst. Tampak boros tapi ternyata efisien karena bab pertama jauh lebih kecil dari keseluruhan buku.
IDDFS mengulang kerja: state di level d dikunjungi d kali. Tapi karena pohon tumbuh eksponensial, kerja berulang itu cuma O(b/(b-1)) ≈ konstan kali lebih lambat dari BFS. Tradeoffnya sangat worth it.
BAGIAN B · [MODERN] PENCARIAN DI AI

Brute force ruang keadaan di sistem AI nyata

BFS/DFS murni langsung collapse di masalah dunia nyata karena b^d meledak. Praktiknya AI pakai tiga strategi:

1. Heuristik (A*) - Pertemuan 9

Tambahkan estimasi jarak ke goal (h(n)) untuk memandu pencarian. Bisa drastis memotong ruang yang dijelajah - dari b^d ke jauh lebih sedikit kalau heuristiknya bagus.

2. Monte Carlo Tree Search (MCTS)

Dipakai AlphaGo: sample jalur secara acak, bukan jelajah semua. Perkiraan nilai simpul bertambah akurat seiring simulasi. O(b^d) tapi dengan konstanta kecil karena sampling.

3. Pruning (Alpha-Beta)

Di game seperti catur: kalau sudah ketemu bahwa cabang ini tidak mungkin lebih baik dari yang sudah ditemukan, potong. Mengurangi O(b^d) ke O(b^(d/2)) dalam kasus terbaik.

Analogi - cari rute di peta. BFS murni = jelajahi semua jalan yang mungkin dalam radius 1 km, lalu 2 km, dst. A* = punya kompas: hanya jelajahi jalan yang mengarah ke tujuan. MCTS = kirim beberapa pramuka secara acak, lihat siapa yang paling sering sampai.

KUNCI JAWABAN

Kunci brute force dan pencarian

1

(n−1)! = 7! = 5.040 rute. Pada 1 μs per rute → 5.040 μs ≈ 5 milidetik. Untuk n=15: (14)! ≈ 87 miliar → ≈ 24 jam. Untuk n=20: ≈ 3.800 tahun.

2

Memori: BFS O(b^d), DFS O(b·d). Optimalitas: BFS ✓ (jika cost seragam), DFS ✗. Kelengkapan: BFS ✓, DFS ✗ (bisa loop). Untuk labirin terbatas: BFS - karena menjamin solusi terpendek.

3

Node yang dijelajahi BFS: 1+4+16+64+256+1024+4096 = 5.461 node (total Σ 4^i dari i=0 ke 6). Memori: 5.461 × 100 byte ≈ 546 KB. Masih sangat ringan untuk kasus ini.

4

IDDFS punya optimalitas dan kelengkapan BFS (O(b^d)) dengan memori DFS (O(b·d)). Pengulangan level-k mengunjungi O(b^k) node, tapi mayoritas kerja ada di level d → total = O(b^d · d/(d-1)) ≈ O(b^d). Faktor konstan b/(b-1) diabaikan asimtotik.

5

BFS untuk konfigurasi sederhana itu ekspansi ~20–100 node. DFS tanpa pembatas kedalaman bisa jauh lebih banyak karena tidak optimal. Perhatikan set seen - tanpa itu BFS tidak pernah selesai di state space yang berputar.
