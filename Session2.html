KERANGKA TEORI · 5W1H

Rekurens - kenapa ada, untuk siapa, dan bagaimana memakainya

What - Apa?

Persamaan rekurens mendefinisikan T(n) dalam bentuk T(n/b) atau T(n−1). Tiga alat: recursion tree untuk intuisi visual, substitusi untuk pembuktian formal, Master Theorem untuk jawaban cepat T(n)=aT(n/b)+f(n).

Why - Mengapa?

Algoritma rekursif tidak bisa dianalisis dengan menghitung loop biasa. Tanpa rekurens, kita tidak bisa tahu Merge Sort itu Θ(n log n) atau Strassen Θ(n^2.807). Rekurens adalah bahasa resmi untuk semua algoritma divide & conquer.

Who - Siapa?

Developer backend (quicksort, mergesort), peneliti ML yang analisis training complexity, dan kandidat technical interview Google/Meta yang ditanya "berapa kompleksitas fungsi rekursif ini?" - wajib hafal tiga kasus Master Theorem.

When - Kapan?

Setiap kali fungsi memanggil dirinya sendiri dengan input lebih kecil. Juga untuk D&C, binary search, tree traversal, dan rekursi di DP. Kapan pun ada "T(n) bergantung pada T(n/k) atau T(n−k)".

Where - Di mana?

Di analisis Merge Sort, Quick Sort, Binary Search, Karatsuba, Strassen, BST operations, dan sistem file rekursif. Master Theorem dipakai langsung di whiteboard interview dan paper algoritma.

How - Bagaimana?

(1) Tulis rekurens T(n) dari kode. (2) Pilih alat: tree untuk intuisi, substitusi untuk bukti formal, Master Theorem untuk solusi cepat. (3) Verifikasi numerik: cek rasio T(n)/g(n) konvergen ke konstanta.

BAGIAN 1 · MOTIVASI

Mengapa fungsi rekursif tidak bisa dianalisis seperti loop?

Loop kita hitung langsung: "berapa kali baris dalam dijalankan?" Mudah.

Fungsi rekursif berbeda: dia memanggil dirinya sendiri. Biayanya bergantung pada berapa kali dia dipanggil dan seberapa besar panggilan itu.

Merge Sort - biaya di mana?

def merge_sort(A):
    if len(A) <= 1: return A
    mid = len(A) // 2
    L = merge_sort(A[:mid])   # ← T(n/2)
    R = merge_sort(A[mid:])   # ← T(n/2)
    return merge(L, R)        # ← biaya n
# Rekurens: T(n) = 2T(n/2) + n
Kuncinya: tulis persamaan dulu. T(n) = 2T(n/2) + n. Baru selesaikan persamaan itu - itulah rekurens.

Binary Search - beda lagi

def bsearch(A, lo, hi, x):
    mid = (lo + hi) // 2
    if A[mid] == x: return mid
    if A[mid] < x:
        return bsearch(A, mid+1, hi, x)
    return bsearch(A, lo, mid-1, x)
# Rekurens: T(n) = T(n/2) + 1

Binary Search hanya satu subpanggilan dengan ukuran n/2, biaya penggabungan 1.

Analogi: Rekurens itu seperti tagihan berjenjang. Total tagihan = tagihan anak cabang kiri + tagihan anak cabang kanan + biaya kantor pusat. Kita perlu formula untuk tahu totalnya.

BAGIAN 3 · SUBSTITUSI

Metode Substitusi - tebak bentuk, buktikan dengan induksi

Dua langkah: (1) Tebak T(n) ≤ c · g(n). (2) Substitusi ke rekurens, cari c yang membuat pernyataan valid.

Contoh: T(n) = 2T(n/2) + n

Tebak: T(n) ≤ c · n log₂n
T(n) ≤ 2 · c·(n/2)·log₂(n/2) + n
   = c·n·(log₂n − 1) + n
   = c·n log₂n − (c−1)n
   ≤ c·n log₂n   asal c ≥ 1 ✓

Pilih c = 2, n₀ = 2. Kasus dasar cek T(2) = 2T(1)+2 = 4 ≤ 2·2·log₂2 = 4. ✓ Selesai.
Jebakan umum: Tebak T(n) = O(n) untuk T(n) = 2T(n/2) + n. Substitusi: T(n) ≤ 2·c·(n/2) + n = cn + n = (c+1)n. Ini tidak pernah ≤ cn karena c terus bertambah. Tebakan salah!
Analogi - cari ukuran baju. Tebak dulu ukurannya. Coba pakai (substitusi). Kalau muat, selesai. Kalau tidak, ganti tebakan. Metode substitusi persis begini - tebak, cek, sesuaikan.

Cara memilih tebakan

Gambar recursion tree dulu → lihat pola biaya per level → buat hipotesis → buktikan. Atau pakai Master Theorem langsung sebagai "spoiler" untuk verifikasi.

BAGIAN 4 · MASTER THEOREM

Master Theorem - T(n) = aT(n/b) + Θ(nᵈ): tiga kasus

Bandingkan d (pangkat biaya gabungan) dengan log_b(a) (pertumbuhan jumlah submasalah).

Kasus 1 - Daun mendominasi (d < log_b a)

Θ(n^(log_b a))

Contoh: Strassen - T(n)=7T(n/2)+n², log₂7≈2.807 > 2 → Θ(n^2.807)

Kasus 2 - Seimbang (d = log_b a)

Θ(nᵈ · log n)

Contoh: Merge Sort - T(n)=2T(n/2)+n, log₂2=1=d → Θ(n log n)

Kasus 3 - Akar mendominasi (d > log_b a)

Θ(nᵈ)

Contoh: T(n)=2T(n/2)+n², log₂2=1 < 2=d → Θ(n²)

BAGIAN 5 · AKRA-BAZZI

Di luar Master Theorem - rekurens subsoal berbeda ukuran

Master Theorem hanya berlaku jika semua subsoal ukurannya sama (n/b). Ada kasus subsoal berbeda ukuran:

Contoh: T(n) = T(n/2) + T(n/3) + n

Cari p sehingga: (1/2)ᵖ + (1/3)ᵖ = 1

Untuk p=1: 1/2 + 1/3 = 5/6 < 1 → p > 1? Tidak, f(n)=n mendominasi.

Solusi numerik: p ≈ 0.788. Karena f(n)=n dan ∫ n/n^(p+1) dn menyumbang, hasilnya T(n) = Θ(n).

Analogi bagi tugas tidak rata. Bos kasih 1/2 pekerjaan ke tim A dan 1/3 ke tim B. Total bobot = 5/6 < 1 per level, artinya beban berkurang tiap level. Akra-Bazzi menghitung "secara berapa cepat" beban itu berkurang.

KUNCI JAWABAN

Kunci - bandingkan dengan jawabanmu

1

log₂4 = 2. a) d=1 < 2 → Kasus 1 → Θ(n²).   b) d=2 = 2 → Kasus 2 → Θ(n² log n).   c) d=3 > 2 → Kasus 3 → Θ(n³).

2

Level 0: 1 subsoal ukuran n, biaya n. Level 1: 3 subsoal ukuran n/3, biaya 3×(n/3)=n. Level k: biaya n selalu. Jumlah level = log₃n + 1. Total = n·(log₃n+1) → Θ(n log n).

3

Tebak T(n) ≤ c·log₂n. Substitusi: T(n) = T(n/2)+1 ≤ c·log₂(n/2)+1 = c·(log₂n−1)+1 = c·log₂n−(c−1). Ini ≤ c·log₂n asal c≥1. Pilih c=1, n₀=2. Terbukti.

4

Naif: T(n)=8T(n/2)+n², log₂8=3 → Θ(n³). Strassen: T(n)=7T(n/2)+n², log₂7≈2.807 → Θ(n^2.807). Mengurangi satu subperkalian (8→7) mengubah dasar logaritma dari 8 ke 7, menurunkan eksponen dari 3 ke 2.807. Untuk n=1000: n³=10⁹ vs n^2.807≈4×10⁸ - penghematan ~60%.
