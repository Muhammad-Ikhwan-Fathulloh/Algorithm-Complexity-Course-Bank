Rekursi dan
Persamaan Rekurens

Merge Sort, Binary Search, Strassen - semuanya mengandung rekurens. Hari ini kita punya tiga alat untuk menyelesaikannya tanpa takut: recursion tree, substitusi, dan Master Theorem.

PETA LANGKAH · KENAPA PENTING

Peta langkah: dari kode rekursif ke rekurens

1. Tulis T(n) dari kode
Hitung berapa kali fungsi memanggil dirinya sendiri, seberapa kecil ukuran subsoalnya, dan berapa kerja di luar pemanggilan.
2. Pilih metode
Recursion tree untuk melihat biaya tiap level, substitusi untuk menebak lalu membuktikan, atau Master Theorem jika bentuknya cocok.
3. Hitung a, b, dan d
Untuk T(n) = aT(n/b) + Θ(nᵈ), bandingkan log_b(a) dengan d. Di sinilah tiga kasus ditentukan.
4. Terapkan kasus yang tepat
Jika log_b(a) lebih besar, kerja ada di daun. Jika sama, tiap level sama besar. Jika lebih kecil, kerja ada di akar.
5. Verifikasi
Hitung T(n) untuk beberapa nilai n secara numerik dan cek apakah rasionya terhadap fungsi kompleksitas stabil.
Kenapa penting: Hampir semua algoritma Divide and Conquer (merge sort, binary search, Karatsuba) dianalisis lewat rekurens. Tanpa ini, kita tidak bisa membandingkan algoritma rekursif.
Master Theorem tidak berlaku untuk semua rekurens. Jika subsoal berukuran tidak sama, pakai Akra-Bazzi atau recursion tree.
KERANGKA TEORI · 5W1H

Rekurens - kenapa ada, untuk siapa, dan bagaimana memakainya

What - Apa?

Persamaan rekurens mendefinisikan T(n) dalam bentuk T(n/b) atau T(n−1). Tiga alat: recursion tree untuk intuisi visual, substitusi untuk pembuktian formal, Master Theorem untuk jawaban cepat T(n)=aT(n/b)+f(n).

Why - Mengapa?

Algoritma rekursif tidak bisa dianalisis dengan menghitung loop biasa. Tanpa rekurens, kita tidak bisa tahu Merge Sort itu Θ(n log n) atau Strassen Θ(n^2.807). Rekurens adalah bahasa resmi untuk semua algoritma divide & conquer.

Who - Siapa?

Developer backend (quicksort, mergesort), peneliti ML yang analisis training complexity, dan kandidat technical interview Google/Meta yang ditanya "berapa kompleksitas fungsi rekursif ini?" - wajib hafal tiga kasus Master Theorem.

When - Kapan?

Setiap kali fungsi memanggil dirinya sendiri dengan input lebih kecil. Juga untuk D&C, binary search, tree traversal, dan rekursi di DP. Kapan pun ada "T(n) bergantung pada T(n/k) atau T(n−k)".

Where - Di mana?

Di analisis Merge Sort, Quick Sort, Binary Search, Karatsuba, Strassen, BST operations, dan sistem file rekursif. Master Theorem dipakai langsung di whiteboard interview dan paper algoritma.

How - Bagaimana?

(1) Tulis rekurens T(n) dari kode. (2) Pilih alat: tree untuk intuisi, substitusi untuk bukti formal, Master Theorem untuk solusi cepat. (3) Verifikasi numerik: cek rasio T(n)/g(n) konvergen ke konstanta.

Cara membaca rumus:
• T(n) = aT(n/b) + f(n): T(n) adalah waktu untuk masalah berukuran n.
• a = jumlah subsoal, b = faktor pengecilan ukuran, f(n) = biaya membagi dan menggabung.
• T(n−1) adalah bentuk lain untuk pengurangan 1 per langkah.
BAGIAN 1 · MOTIVASI

Mengapa fungsi rekursif tidak bisa dianalisis seperti loop?

Loop kita hitung langsung: "berapa kali baris dalam dijalankan?" Mudah.

Fungsi rekursif berbeda: dia memanggil dirinya sendiri. Biayanya bergantung pada berapa kali dia dipanggil dan seberapa besar panggilan itu.

Merge Sort - biaya di mana?

def merge_sort(A):
    if len(A) <= 1: return A
    mid = len(A) // 2
    L = merge_sort(A[:mid])   # ← T(n/2)
    R = merge_sort(A[mid:])   # ← T(n/2)
    return merge(L, R)        # ← biaya n
# Rekurens: T(n) = 2T(n/2) + n
Kuncinya: tulis persamaan dulu. T(n) = 2T(n/2) + n. Baru selesaikan persamaan itu - itulah rekurens.

Binary Search - beda lagi

def bsearch(A, lo, hi, x):
    mid = (lo + hi) // 2
    if A[mid] == x: return mid
    if A[mid] < x:
        return bsearch(A, mid+1, hi, x)
    return bsearch(A, lo, mid-1, x)
# Rekurens: T(n) = T(n/2) + 1

Binary Search hanya satu subpanggilan dengan ukuran n/2, biaya penggabungan 1.

Analogi: Rekurens itu seperti tagihan berjenjang. Total tagihan = tagihan anak cabang kiri + tagihan anak cabang kanan + biaya kantor pusat. Kita perlu formula untuk tahu totalnya.

Recursion Tree - gambar pohon, hitung biaya per level

Cara paling intuitif: gambar pohon pemanggilan. Setiap simpul = satu panggilan. Biaya simpul = f(ukurannya). Jumlahkan per level.

Kesimpulan: log₂n + 1 level, tiap level biaya n → Total = n(log₂n + 1) = Θ(n log n). Ini Merge Sort.
Coba sendiri - breakdown level-by-level
Cara membaca rumus:
• T(n) = 2T(n/2) + n: 2 subsoal berukuran n/2, ditambah biaya n di luar rekursi.
• Level k: 2ᵏ subsoal, masing-masing berukuran n/2ᵏ, sehingga biaya per level = 2ᵏ · n/2ᵏ = n.
• Ada log₂n level, jadi total = n · log₂n = Θ(n log n).
BAGIAN 3 · SUBSTITUSI

Metode Substitusi - tebak bentuk, buktikan dengan induksi

Dua langkah: (1) Tebak T(n) ≤ c · g(n). (2) Substitusi ke rekurens, cari c yang membuat pernyataan valid.

Contoh: T(n) = 2T(n/2) + n

Tebak: T(n) ≤ c · n log₂n
T(n) ≤ 2 · c·(n/2)·log₂(n/2) + n
   = c·n·(log₂n − 1) + n
   = c·n log₂n − (c−1)n
   ≤ c·n log₂n   asal c ≥ 1 ✓

Pilih c = 2, n₀ = 2. Kasus dasar cek T(2) = 2T(1)+2 = 4 ≤ 2·2·log₂2 = 4. ✓ Selesai.
Jebakan umum: Tebak T(n) = O(n) untuk T(n) = 2T(n/2) + n. Substitusi: T(n) ≤ 2·c·(n/2) + n = cn + n = (c+1)n. Ini tidak pernah ≤ cn karena c terus bertambah. Tebakan salah!
Analogi - cari ukuran baju. Tebak dulu ukurannya. Coba pakai (substitusi). Kalau muat, selesai. Kalau tidak, ganti tebakan. Metode substitusi persis begini - tebak, cek, sesuaikan.

Cara memilih tebakan

Gambar recursion tree dulu → lihat pola biaya per level → buat hipotesis → buktikan. Atau pakai Master Theorem langsung sebagai "spoiler" untuk verifikasi.

Cara membaca rumus:
• Langkah 1 (tebak): T(n) ≤ c·n·log₂n, dengan c konstanta yang belum diketahui.
• Langkah 2 (substitusi): masukkan tebakan ke rekurens, lalu cari c yang membuat ketidaksamaan benar.
• Jika berhasil, terbukti T(n) = O(n log n). Ini bukti formal dari hasil recursion tree.
BAGIAN 4 · MASTER THEOREM

Master Theorem - T(n) = aT(n/b) + Θ(nᵈ): tiga kasus

Bandingkan d (pangkat biaya gabungan) dengan log_b(a) (pertumbuhan jumlah submasalah).

Kasus 1 - Daun mendominasi (d < log_b a)

Θ(n^(log_b a))

Contoh: Strassen - T(n)=7T(n/2)+n², log₂7≈2.807 > 2 → Θ(n^2.807)

Kasus 2 - Seimbang (d = log_b a)

Θ(nᵈ · log n)

Contoh: Merge Sort - T(n)=2T(n/2)+n, log₂2=1=d → Θ(n log n)

Kasus 3 - Akar mendominasi (d > log_b a)

Θ(nᵈ)

Contoh: T(n)=2T(n/2)+n², log₂2=1 < 2=d → Θ(n²)

Kalkulator Master Theorem
Isi a, b, d lalu klik Selesaikan
Cara membaca rumus:
• Bandingkan d (pangkat f(n) = nᵈ) dengan log_b(a) (pertumbuhan jumlah subsoal).
• Kasus 1: d < log_b a → T(n) = Θ(n^(log_b a)). Daun mendominasi.
• Kasus 2: d = log_b a → T(n) = Θ(nᵈ log n). Tiap level sama besar.
• Kasus 3: d > log_b a → T(n) = Θ(nᵈ). Akar mendominasi.

BAGIAN 5 · AKRA-BAZZI

Di luar Master Theorem - rekurens subsoal berbeda ukuran

Master Theorem hanya berlaku jika semua subsoal ukurannya sama (n/b). Ada kasus subsoal berbeda ukuran:

Contoh: T(n) = T(n/2) + T(n/3) + n

Cari p sehingga: (1/2)ᵖ + (1/3)ᵖ = 1

Untuk p=1: 1/2 + 1/3 = 5/6 < 1 → p > 1? Tidak, f(n)=n mendominasi.

Solusi numerik: p ≈ 0.788. Karena f(n)=n dan ∫ n/n^(p+1) dn menyumbang, hasilnya T(n) = Θ(n).

Analogi bagi tugas tidak rata. Bos kasih 1/2 pekerjaan ke tim A dan 1/3 ke tim B. Total bobot = 5/6 < 1 per level, artinya beban berkurang tiap level. Akra-Bazzi menghitung "secara berapa cepat" beban itu berkurang.

Rekurens lain yang tidak bisa pakai Master Theorem langsung

RekurensHasil
T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+nΘ(n log n)
T(n)=T(n/3)+T(2n/3)+nΘ(n log n)
T(n)=T(n/2)+T(n/4)+T(n/8)+nΘ(n log n)
Untuk kursus ini: yang perlu diingat adalah - jika subsoal ukurannya berbeda, Master Theorem tidak langsung berlaku. Akra-Bazzi adalah alat yang tepat, tapi perhitungannya lebih rumit.
Cara membaca rumus:
• Dipakai jika subsoal berukuran berbeda, misalnya n/2 dan n/3.
• Langkah: cari p yang memenuhi (1/2)ᵖ + (1/3)ᵖ = 1. Nilai p ini menentukan pangkat utama hasil.
• Hasilnya Θ(nᵖ(1 + ∫ …)), dengan integral dari f(u) terhadap u. Untuk kursus ini cukup tahu bentuk umumnya.

Bedah Rumus 1/4 · Langkah 3: dari hitungan ke kode & kasus nyata

Mengurutkan file log yang lebih besar dari RAM

Implementasi di proyek nyata

External merge sort di database (misalnya ORDER BY pada tabel 100 GB) memecah data menjadi potongan yang muat di RAM, mengurutkan tiap potongan, lalu menggabungkan. Rekurens yang sama menjamin waktu Θ(n log n) bahkan untuk data sebesar itu.

Contoh lain di kasus ini

1

n = 8

Level: 8 → 4,4 → 2,2,2,2 → 1×8. Ada log₂ 8 + 1 = 4 level.

2

Biaya per level

masing-masing 8 (total ukuran potongan selalu 8).

3

Total

8 × 3 level kerja + 8 daun = 8·3 + 8 = 32 = n log₂n + n ✓

4

n = 1 juta

≈ 10⁶ × 20 = 2×10⁷ operasi - selesai dalam hitungan detik.

Kode Python

def T(n):
    # hitung biaya rekurens secara langsung
    if n == 1: return 1
    return 2 * T(n // 2) + n

import math
for n in (8, 1024, 2**16):
    print(n, T(n), int(n * math.log2(n) + n))  # sama persis

Bedah Rumus 2/4 · Langkah 1: cara membaca

Master Theorem

T(n) = a·T(n/b) + Θ(nd)  ⇒  bandingkan d dengan logb a

Cara membaca rumus ini

“T dari n sama dengan a kali T dari n per b, ditambah Theta n pangkat d. Untuk menyelesaikannya, bandingkan d dengan logaritma basis b dari a.”
1

d < log_b a → Θ(n^{log_b a})

Kasus 1: daun yang dominan. Jumlah subsoal tumbuh lebih cepat daripada kerja per level.

2

d = log_b a → Θ(nᵈ log n)

Kasus 2: seimbang. Setiap level biayanya sama, dikali banyaknya level.

3

d > log_b a → Θ(nᵈ)

Kasus 3: akar yang dominan. Kerja di level teratas mengalahkan semuanya.

Arti tiap simbol

abanyaknya panggilan rekursif (≥ 1)
bfaktor pengecilan ukuran (> 1)
dpangkat biaya kerja di luar rekursi
log_b a“pangkat kritis”: laju pertambahan jumlah daun
Intuisinya: Ini adu tarik antara perbanyakan subsoal (a) dan pengecilan ukuran (b). log_b a mengukur seberapa cepat daun bertambah; d mengukur seberapa berat kerja di tiap simpul.

Memperkirakan algoritma rekursif sebelum menulisnya

Implementasi di proyek nyata

Saat merancang pemrosesan citra berbasis quadtree (kompresi peta, deteksi area di citra satelit), engineer bisa langsung tahu bahwa membagi gambar n×n menjadi 4 kuadran dengan kerja konstan tetap Θ(n²). Kalau kerja per simpul dinaikkan menjadi Θ(n²), maka d=2=log₂4 → Θ(n² log n). Keputusan desain bisa diambil di papan tulis.

Kode Python

import math
def master(a, b, d):
    c = math.log(a, b)
    if abs(d - c) < 1e-9: return f"Theta(n^{d} log n)"
    if d < c:             return f"Theta(n^{c:.3f})"
    return f"Theta(n^{d})"

print(master(2, 2, 1), master(3, 2, 1), master(7, 2, 2))

Bedah Rumus 3/4 · Langkah 1: cara membaca

Rekurens kurang-satu: T(n) = T(n−1) + n

T(n) = T(n−1) + n  =  n + (n−1) + … + 1  =  n(n+1)/2 = Θ(n²)

Cara membaca rumus ini

“T dari n sama dengan T dari n kurang satu ditambah n. Kalau dibuka terus, hasilnya n tambah n kurang satu sampai satu, yaitu n kali n tambah satu per dua, Theta n kuadrat.”
1

Bentuk “minus satu”

subsoal hanya lebih kecil SATU elemen - bukan separuh.

2

Unrolling (buka berulang)

T(n) = n + T(n−1) = n + (n−1) + T(n−2) = ...

3

Kenali deretnya

Jumlah 1..n = n(n+1)/2 (rumus Gauss) → Θ(n²).

Arti tiap simbol

T(n−1)panggilan rekursif dengan data berkurang satu
+ nkerja linear di tiap panggilan (misalnya mencari minimum)
n(n+1)/2hasil penjumlahan semua level
Intuisinya: Rekursi yang hanya “mengupas satu elemen” membuat pohonnya menjadi rantai sepanjang n, bukan pohon setinggi log n. Itulah mengapa quicksort dengan pivot buruk jatuh ke Θ(n²).

Quicksort pada data yang sudah terurut

Banyak data produksi sudah hampir terurut (ID auto-increment, timestamp). Library seperti C++ std::sort (introsort) dan Java memakai pivot median-of-three/acak dan beralih ke heapsort untuk menghindari jebakan T(n) = T(n−1) + n.

Contoh lain di kasus ini

1

Data

[1, 2, 3, ..., n] dan pivot = elemen pertama.

2

Partisi

pivot 1 → kiri kosong, kanan n−1 elemen; kerja partisi n.

3

Rekurens

T(n) = T(n−1) + n.

4

n = 10.000

≈ 50 juta perbandingan, bukan ~130 ribu seperti kasus rata-rata.

Kode Python

def T(n):
    total = 0
    while n > 0:          # unrolling sebagai loop
        total += n
        n -= 1
    return total

print(T(10_000), 10_000 * 10_001 // 2)  # sama

Rekurens Fibonacci naif

T(n) = T(n−1) + T(n−2) + 1  ⇒  T(n) = Θ(φn),   φ = (1+√5)/2 ≈ 1,618

Cara membaca rumus ini

“T dari n sama dengan T dari n kurang satu ditambah T dari n kurang dua ditambah satu. Hasilnya Theta phi pangkat n, dengan phi sama dengan satu tambah akar lima per dua, kira-kira satu koma enam satu delapan.”
1

Dua panggilan, ukuran hampir sama

n−1 dan n−2 hampir sebesar n, jadi pohonnya bercabang dua tanpa menyusut cepat.

2

φ (phi) = rasio emas

akar dari x² = x + 1; laju pertumbuhan bilangan Fibonacci.

3

Θ(φⁿ)

eksponensial: setiap n bertambah 1, biaya ×1,618.

Arti tiap simbol

T(n−1), T(n−2)dua subsoal yang saling tumpang-tindih
+1kerja konstan (satu penjumlahan)
φ ≈ 1,618basis pertumbuhan eksponensial
Intuisinya: fib(5) memanggil fib(3) dua kali, fib(2) tiga kali, dan seterusnya. Subsoal yang sama dihitung ulang berkali-kali - inilah tanda bahwa butuh memoisasi (dynamic programming).

Soal: Hitung banyaknya panggilan fungsi fib_naif(6): P(n) = P(n−1) + P(n−2) + 1, P(0) = P(1) = 1.

Langkah hitung (kertas & kalkulator)

1

Dasar

P(0) = 1, P(1) = 1

Naik satu per satu

P(2) = 1+1+1 = 3, P(3) = 3+1+1 = 5, P(4) = 5+3+1 = 9

Lanjut

P(5) = 9+5+1 = 15, P(6) = 15+9+1 = 25

4

Lihat rasionya

25 / 15 ≈ 1,67 → mendekati φ ≈ 1,618

5

Dengan memo

fib(0)…fib(6) masing-masing sekali = 7 panggilan

Resolusi dependensi tanpa cache

Implementasi di proyek nyata

Pola ini muncul di build system atau package manager yang menelusuri dependensi secara rekursif: modul A butuh B dan C, B juga butuh C, dan seterusnya. Tanpa cache “sudah diproses”, waktu meledak secara eksponensial. Webpack, Bazel, dan pip semua menyimpan hasil per modul.

Contoh lain di kasus ini

1

n = 30

φ³⁰ ≈ 1,9 juta panggilan.

2

n = 40

φ⁴⁰ ≈ 228 juta panggilan - beberapa detik di Python.

3

n = 50

≈ 28 miliar panggilan - praktis tidak selesai.

4

Dengan memo

setiap fib(k) dihitung sekali → n panggilan → Θ(n).

Kode Python

from functools import lru_cache

def fib_naif(n):            # Theta(phi^n)
    return n if n < 2 else fib_naif(n-1) + fib_naif(n-2)

@lru_cache(maxsize=None)
def fib_memo(n):            # Theta(n)
    return n if n < 2 else fib_memo(n-1) + fib_memo(n-2)

print(fib_memo(90))   # instan

LATIHAN

Soal rekurens - coba sebelum lihat kunci

1

Gunakan Master Theorem untuk: a) T(n)=4T(n/2)+n    b) T(n)=4T(n/2)+n²    c) T(n)=4T(n/2)+n³. Tentukan kasus dan hasilnya untuk masing-masing.

2

Gambarkan recursion tree untuk T(n) = 3T(n/3) + n. Berapa biaya per level? Berapa level totalnya? Simpulkan Θ-nya.

3

Buktikan dengan metode substitusi bahwa T(n) = T(n/2) + 1 adalah O(log n). Tulis langkah formal: tebak, substitusi, pilih c dan n₀.

4

Mengapa Strassen lebih cepat dari perkalian matriks naif? Tunjukkan bagaimana mengurangi satu subperkalian rekursif mengubah eksponen kompleksitas waktu secara fundamental.

KUNCI JAWABAN

Kunci - bandingkan dengan jawabanmu

1

log₂4 = 2. a) d=1 < 2 → Kasus 1 → Θ(n²).   b) d=2 = 2 → Kasus 2 → Θ(n² log n).   c) d=3 > 2 → Kasus 3 → Θ(n³).

2

Level 0: 1 subsoal ukuran n, biaya n. Level 1: 3 subsoal ukuran n/3, biaya 3×(n/3)=n. Level k: biaya n selalu. Jumlah level = log₃n + 1. Total = n·(log₃n+1) → Θ(n log n).

3

Tebak T(n) ≤ c·log₂n. Substitusi: T(n) = T(n/2)+1 ≤ c·log₂(n/2)+1 = c·(log₂n−1)+1 = c·log₂n−(c−1). Ini ≤ c·log₂n asal c≥1. Pilih c=1, n₀=2. Terbukti.

4

Naif: T(n)=8T(n/2)+n², log₂8=3 → Θ(n³). Strassen: T(n)=7T(n/2)+n², log₂7≈2.807 → Θ(n^2.807). Mengurangi satu subperkalian (8→7) mengubah dasar logaritma dari 8 ke 7, menurunkan eksponen dari 3 ke 2.807. Untuk n=1000: n³=10⁹ vs n^2.807≈4×10⁸ - penghematan ~60%.
